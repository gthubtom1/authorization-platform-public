# 旧参考隔离与当前通用运行时

平台维护的包内源码保持可追溯。下表保留旧参考模块的问题位置和不能回退的规则；现行桌面入口已调用 `src/current_runtime.rs` 的真实通用链，不再调用这些旧DTO/mock/codec授权。验收与目标软件缺口见 `授权启动器模板/docs/CURRENT-RUNTIME.md`。来源路径相对于包内 `授权启动器模板/`。

| ID / 旧位置 | 当前差异与软件副本必须采用的规则 | 必要反例 |
|---|---|---|
| B1 src/platform.rs 的 PlatformResponse 解析；src/authorization.rs canonical_payload | 解析投影丢签名/字段，旧DTO按 product_id/protocol/snapshot_id/数组模块重建。保留完整原 JSON 对象，先按当前端点合同校验；只删除 integrity.signature 单字段，保留其余 integrity，JCS/Ed25519 验签成功后才投影；A-core 独立封装校验。旧DTO不能重建平台签名输入 | 改动任意已签字段均拒绝；未知 key、错身份拒绝；完整平台对象与删整个integrity的字节流不可互换 |
| B2 src/session.rs apply_denial；tests/session.rs unavailable | 旧失败路径仅推迟60秒，可持续到卡到期。当前LiveSession保留卡到期与最后成功窗口两个截止；失败/429/重试不能延期。默认宽限0，超窗即停；grace_until是expires_at加策略宽限，取二者差作为成功窗口宽限时长，仍不得越过卡到期 | 连续断网及429最终停用；失败重试不能延长锚点；网络失败不伪报“卡过期” |
| B3 src/authorization.rs cache accept/not_modified；src/session.rs NotModified | 同revision不等于同一请求：新request_id/time/cache_until可变。有效not_modified合并当前已验证缓存并更新在线时间元数据；已终态不能恢复；旧1024条台账需有界过期/淘汰规则，不能长时运行自行报错 | 同revision连续正常心跳、not_modified推进next_verify_at、旧响应重放拒绝、连续超过1024次不误锁、终态不能靠not_modified恢复 |
| B4 protocol/launch-ticket.v1.md | 当前说明已替换为公开合同；TTL=min(签发+现行策略TTL,授权到期)。未知结果复用原body/request/idempotency/nonce，新逻辑请求才换全部值。核销撤销/解绑/过期/风险硬失败停用；网络失败不延长已有权限 | 丢响应重试不造第二张票；同键改nonce冲突；短卡票据不晚于卡到期；核销硬失败不可继续 |
| B6 src/platform.rs bounded_text；src/codec.rs unicode escape | 参考按UTF-8字节限字段、拒绝合法代理对；平台字段长度按Unicode字符，传输总字节限制独立。用成熟JSON/JCS解析，接受合法emoji代理对并拒绝孤立代理项，不用UTF-16单元数冒充字符数 | 合法64中文联系方式接受；直接emoji与转义代理对解码等价；孤立代理项/超长字符串拒绝 |
| B7 src/authorization.rs ErrorCode；protocol/device-proof.v1.json | 当前交付协议已同步5动作；旧枚举仍可能用AUTHORIZATION_REVOKED/BLOCKED。公共真实LICENSE_REVOKED/BLOCKED等按索引处理，不全局改名覆盖本地错误；未知码失败关闭 | 五proof动作均能验证；请求无action字段；公共与本地码分域测试；未知不可重试码不能放行 |
| C1 protocol/authorization-a-ui.v1.schema.json；src/ui.rs | Schema已接受实现已有notice别名。平台modules.notice对应公告内容announcement；UI旧announcement别名只在边界归一，不改变平台五键。不要同时配置两个别名形成重复卡片 | notice/announcement分别通过UI Schema与实际渲染；重复语义去重；顶层不把announcement改名notice |
| C2 scripts/start-here.ps1/init-product.ps1 | 两脚本只作可选模板状态/EXE基线辅助。start-here枚举TemplateRoot不能当原软件盘点，下一步文字不能覆盖本包AI入口。InputPath是基线来源；默认core/<ProductId>.exe不是原软件运行路径，也不会自动部署该文件 | 源码无EXE可先接线；辅助脚本不初始化平台仓库通用包；真实core_path、工作目录/依赖/启动参数逐项验证；缺核心功能门仍PARTIAL |
| C3 init-product 的 ProductId/profile-default | 新本地产品推荐product_id=software_id（符合本地标识限制时）；已有product_id保留，在本软件记录稳定映射到software_id/profile_id/client_id，不重建平台身份。沿用UiModuleCatalog时UI profile_id必须等于真实平台profile_id，不保留profile-default。device/client/软件版本都不由本地product_id替代 | 真实stable与占位profile-default不同应暴露；两个产品缓存/UI不串；修改本地配置而非反改下载JSON |

当前准备工具保留平台字段原值，严格核对包内三份支持合同，不读取目标软件自己的同名protocol目录；非Windows/x64目标、无法解析的最低版本仍给出warning + PARTIAL。当前Binding::load真实消费准备结果、来源哈希、固定公钥、API和合同；真实构建版本必须显式提供。公共更新查询和下载支持已登记的点号软件/Profile身份；查询必须提供真实三段version，缺失、非法或超长值返回400，不解释为“已经最新”。

本轮D1–D10通用实现集中在current_runtime、现有桌面入口、WebViewRenderer::run_live和包内JS：平铺五POST/proof、成熟JSON/JCS/Ed25519、已验证会话、同revision/not_modified/续期、成功截止、真issued/consumed许可、当前A-core签名、本机接口、宿主/UI动态快照、配置消费、空渠道隐藏。原161项参考回归保留；新原生反例与真实socket/隐藏WebView2另验。

具体软件仍必须实施稳定硬件采集、核心每个功能门、直开拒绝、可信父子/本机认证、进程树停用与双机挤机；不能将通用测试扩大为任意软件已完成。软件项目《授权平台对接文档.md》逐ID记录通过/待验及具体修改文件。
