# 接入接口、字段来源和平台能力

配合本软件后台下载的 JSON、[接口字段索引.json](接口字段索引.json)、[客户端API合同](客户端API合同.md) 和 [模板兼容差异](模板兼容差异.md) 使用。此文是技术查询表；执行指令仍以 09 和下载 JSON 的 ai_handoff 为源。表中路径变量不能改写下载原件。`S/P/R` 表示 software_id/profile_id/release_id。

## 先判断接入模型和软件输入

平台通用模型是在线卡密、服务端判定、设备绑定和周期验证，不按软件名堆接口分支。Python、C#、C++、Rust、JavaScript 等语言可按协议实现 A；这不代表随包 Rust 启动器已适配所有语言/系统。当前参考桌面 UI 是 Windows/WebView2，设备安全存储有 Windows 实现边界；macOS/Linux/其他架构需自行实现对应 UI、存储、设备身份与本地通道并实测。长期完全离线、浮动席位、SSO、支付不是本 v1 已支持的授权模型。

| 输入 | 接入方式与证据 | 结果边界 |
|---|---|---|
| 自己开发或获准修改的源码 | 从真实启动入口、后台任务和每个受保护业务入口加入实时功能门；A 负责平台调用，核心只访问本机 A；先保留源码基线，可在尚无 EXE 时开发 | `native_core` 需真实核心本地合同及直开仍被保护的证据 |
| 明确获准维护/再发行的第三方程序，只有 EXE | 先保存不可变基线，确认运行依赖、已有接口和可维护位置，再选择受支持的适配方式；遇到保护或未知行为时按宿主的逆向分析工作流处理，不能盲改程序 | `legacy_auth` 只有在旧边界能实际接到现行合同、且功能门可证明有效时成立；不是“仅 EXE”的同义词 |
| 只能在程序外增加启动窗口 | 记录 `wrapper_only`，验证绕开启动器直开核心会发生什么 | 核心仍可直接使用时保持 PARTIAL/BLOCKED，不能宣称完成核心保护 |

输入是源码或二进制，与 compatibility 的三个值是两件事；不能凭文件类型自动选择或宣称保护强度。这里没有具体第三方目标，未对任何第三方程序作适配保证。

## 配置值到底对应哪里

| 来源 | 发给平台/本地的字段 | 使用规则 |
|---|---|---|
| `platform.base_url` | HTTPS origin | 合并 api 相对路径，保留尾斜杠，不用模板演示网址 |
| `software.software_id/profile_id/client_id/target/arch/channel` | 同名六个请求字段 | 固定构建身份，逐字符匹配；名称仅展示，不依据名称猜 ID |
| `platform.contract_version` | POST 的 `contract_version` | 当前 authorization.v1；下载格式 v2 不表示协议都改 v2 |
| `platform.authorization_public_key` / `authorization_public_key_id` | 验签公钥 / integrity.key_id | base64url 无填充，公钥解码32字节；公钥由受控下载交付，运行时不能网络换根 |
| `platform.algorithm/canonicalization` | integrity 相同字段 | 精确 ed25519 / JCS-RFC8785 |
| 软件真实构建 | POST `client_version`；更新 GET `version` | 更新用真实三段数字；`minimum_client_version` 只是最低支持版本 |
| `software.capabilities` | 能力定义清单 | 不等于本卡实得权益；最终用已验签响应 capabilities/entitlements；空清单不猜键 |
| 本机稳定硬件指纹 | POST 顶层 `installation_id` | 重装不随机更换；响应的 device_scope 是平台确认结果，不能当请求字段回传 |
| 本机生成的 Ed25519 设备密钥 | `device_public_key/device_proof` | 私钥只在客户设备安全保存；不是平台签名私钥，也不是 A-core 本地会话密钥 |
| 当前一次逻辑请求 | request_id / idempotency_key / nonce | 新操作新值；结果未知重试复用原 body 和全部三个值；proof action 在签名消息中，POST 无顶层 action |
| 本地产品配置 | product_id / UI profile_id / core_path | 见兼容差异 C3；不修改平台 JSON 去迁就占位值 |

## 客户端准确端点

| JSON api 键 | 方法与路径 | 特有请求内容 | 成功响应 |
|---|---|---|---|
| activate | POST `/api/v1/public/licenses/activate` | license_key | 顶层已签名 authorization.v1 |
| verify | POST `/api/v1/public/licenses/verify` | authorization_id；可选 known_authorization_revision/known_config_version | 同协议；not_modified 仍有新的在线时间元数据 |
| deactivate | POST `/api/v1/public/licenses/deactivate` | authorization_id | 已签名 unbound，必须停用 |
| launch_ticket | POST `/api/v1/public/licenses/launch-ticket` | authorization_id，proof action=launch-ticket | issued + ticket + integrity |
| consume_launch_ticket | POST `/api/v1/public/licenses/launch-ticket/consume` | authorization_id、ticket_id，proof action=ticket-consume | consumed 九字段，无 integrity |
| releases | GET `/api/v1/public/software/S/profiles/P/releases/` | query client_id/target/arch/channel/version | 顶层 has_update，详情在 release |
| 响应给出的 download_url | GET `/api/v1/public/software/S/profiles/P/releases/R/download/` | 可选本站 ZIP，无卡密 query | ZIP 字节；失败 JSON error |

五个 POST 不带末尾 `/`；更新/下载带 `/`。发送 application/json、X-Request-Id、Idempotency-Key；后两项与 body 一致。请求32KiB、解析深度有限，不附整份配置、后台字段或任意 extensions。七元身份含 contract_version，所有 POST 都带设备字段和真实 client_version。核销额外 ticket_id 不在 device-proof.v1 的签名消息字段集合中；按交付协议精确构造，不擅自扩展消息。

没有统一 data/response 外壳。HTTP 200 不代表授权有效；先看端点合同、身份、签名、decision 和时间。普通 error 对象不是完整授权信封，也可能与已签名状态信封分别出现；未知硬错误失败关闭。收到 HTML、重定向到登录、非JSON或截断响应记通信失败，不能模拟 allow。

当前无独立公共 manifest 配置GET。公告/联系/购买/配置版本从普通授权响应取得；版本更新另查 releases。更新无版本时 release=null；有版本但不更新时 release 仍可存在。只在 has_update=true 且版本更高时提示，用户点击打开 `release.update_open_url`。本站下载仅在主动选用该通道时使用 `release.download_url` 并做包验证/回滚。不要在顶层找 version/update_open_url，不用 size/sha256 代替 package_size/package_sha256。ISO generated_at/详情日期与授权整数秒是不同类型。

## UI、能力与后台动作怎样传播

普通响应 `modules` 固定 contact/notice/purchase/qr/update 五键，值可以 null。公告是顶层 announcement，对应 modules.notice；UI 旧配置名 announcement 是兼容别名。support.purchase_url/qq/wechat 只来自实际发卡下游及有效实例覆盖，Profile 不能兜底购买/联系方式。空就隐藏；联系方式按文本原样展示，购买链接交系统浏览器，不内嵌并不拼卡密。现行普通授权 update/modules.update 可为 null，不能因此跳过 releases 查询。

| 平台能力 | 客户软件怎样参与 |
|---|---|
| F-001/003/004/028 软件、经营范围、套餐、自助接入 | 管理员配置；软件读取本软件 JSON，实际授权从平台响应取，不调用后台改范围/套餐 |
| F-002/005 下游和账号 | 平台页面处理，最终客户不创建平台账号 |
| F-006/007/008/009/010/011 额度、流水、发卡、扣款、回收、额度收回 | 平台及下游处理；客户仅输入卡密激活，不持有下游账号或发卡权限 |
| F-012/013 激活验证、授权实例与设备绑定 | activate/verify/deactivate + 设备证明、本地功能门；授权实例和卡密不是同一个对象 |
| F-014/015 撤销和风控 | 收到硬失败立即锁定，不用本地缓存恢复；运行中通过下一次 verify 传播 |
| F-016/017 支持、配置与公告 | 按 support/announcement/modules/config_version 读并刷新；不能传 downstream_id 选内容 |
| F-018/025 版本、更新、归档改号 | GET releases；归档/改号是后台动作，下次查询看真实最新发布 |
| F-019/020 审计、清理和统计 | 平台运营，不把完整卡密/私钥写日志；客户端不调用审计/清理/统计后台接口 |
| F-021/023 备份、恢复和迁移 | 服务器运营，不随客户端交付密钥包、备份口令或数据库 |
| F-022 平台静态预览 | 平台验证工具，不是客户端真实验收证据 |
| F-024 补时间 | 管理员后台续期，下一次 verify 得新 expires_at/revision，运行中核心更新，不重新激活 |
| F-026 在线反套利 | 稳定设备身份、现行换机规则、断网超窗口停用，两机验证挤机 |
| F-027 一次性启动票据 | 按软件明确选用的票据路径签发/核销；不能因开关关闭降级绕过已约定门禁 |

`GET /api/v1/public/quota-settings/` 是平台页面的额度购买入口，不是客户买软件的 support.purchase_url。管理/下游端的注册、发卡、撤销、续期、经营范围、发版和备份接口都需要相应后台身份；客户软件不调用。下载软件配置与公钥的 manage 接口也不用于客户运行时自举。

## 错误和验收资料

接口字段索引中的普通错误码来自授权服务当前静态抛错位置及HTTP出口，附来源位置；它不是每个端点必然返回所有码的承诺。公共 LICENSE_REVOKED/LICENSE_BLOCKED 与参考本地 AUTH_INVALID 等分开映射；未知非可重试错误停用。RATE_LIMITED 按 Retry-After 有界重试，不能冒充被挤机，也不能延长最后有效在线窗口。5xx、断网、解析失败都不产生新的授权。

[fixtures/README.md](fixtures/README.md) 区分完整信封形状、错误响应和故意无效输入。占位签名 fixture-signature 不能真验签，样例时间不表示现行验证周期。实际验收必须用本软件受控配置及测试卡，先单机超过两个验证周期，再错卡、持续断网/429、到期、撤销封禁、补时间、直开核心、渠道空值/Unicode与更新；连续超过1024次验证和 not_modified 刷新须有定向证据。没有两台机器就不能标挤机已验。
