# 备份与维护

## 备份

数据库含管理账号的密码哈希、软件与链接；图片单独存盘。不能只复制正在写的sqlite文件或只留图片。

本地：设置原本站环境和数据路径后，运行 `python manage.py backup_site --output 绝对路径/备份名.zip`。正式容器：`docker compose exec -T app python manage.py backup_site --output /data/backups/manual-日期.zip`，随后用 `docker compose cp app:/data/backups/文件名.zip 安全目录/` 拷出。命令拒绝覆盖同名备份。

备份命令使用SQLite在线快照，再复制媒体；删除图只删引用、暂不物理删，因此快照引用的旧图仍能复制。备份ZIP不含 `.env`/本站密钥，需另在安全位置保存。备份不是加密文件，勿放公开下载目录或代码仓库。需要加密/异地定时备份时由部署AI按真实运行环境配置并验证，不声称本站已自动异地备份。

## 恢复

1. 先停止本站写入，保留当前代码、原`.env`和当前数据的回退备份。
2. 运行`python restore-backup.py 备份.zip 一个全新的空数据目录`。脚本检查路径、数据库物理/外键完整性和数据库引用的每张图片，缺图或不安全路径必须失败；恢复后清空旧会话。不允许覆盖非空目录；失败输出不能启动使用。
3. 使用原本站的`.env`/密钥，将数据挂载切换到恢复目录并设为UID/GID10001可写，再按本目录安装器接线。Docker命名卷场景先恢复到隔离目录，再由部署AI明确核对目标卷后导入；不能随手覆盖运行中的卷。
4. 先在隔离端口核对软件、分类、图片、管理员登录和链接，再切换正式入口。新环境的恢复成功不等于真实域名已经切换。

## 更新与回退

更新前保留上一份代码或镜像摘要、数据库/图片备份及原`.env`。用本站`deploy/install-site.sh`，先停止应用并确认停写，再用一次性容器备份已有数据库及媒体；旧app已停止也不能跳过已有数据。备份失败即停止，成功才迁移，首次无数据库可明确跳过。迁移失败停在错误处，不能把半成功当上线。

数据库迁移未必能由旧代码读取。回退应停止本站，用匹配版本代码与完整备份恢复到新目录，再核对切换；不能只换旧镜像就承诺数据回退。不要删除其他VPS服务、授权平台卷或密钥。

## 长期维护

定期下载并隔离恢复一份备份、检查证书与外链、更新依赖。默认不物理删除孤立图片，磁盘增长应监控；清理需先备份，生成引用差异清单后由维护者明确执行。会话可通过 `manage.py clearsessions` 清理；是否配置计划任务由未来部署手册补记真实实施。
