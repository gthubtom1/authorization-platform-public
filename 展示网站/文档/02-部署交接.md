# 部署交接

给未来负责部署的AI：仅部署这个子目录中的独立展示站。不要连接授权平台数据库、复制授权平台production.env、使用授权卡密密钥，或运行上级仓库的安装器。这里的 `SITE_SECRET_KEY` 只是本站Django会话密钥，独立生成并保管。

本站已部署于showcase.example.com；以下是现行部署合同。实际版本、备份与验证看根部署与恢复/09-正式站上线与回退手册.md，不把步骤文字当上线证明。

## 先确认

取得用户指定的VPS、域名和部署授权。检查系统、已有服务、端口、磁盘与备份。当前Compose只发布`127.0.0.1:18082`，由宿主Nginx终止HTTPS，容器内Nginx负责静态文件和应用转发；不占用宿主80/443，不停其他网站。根目录配套导航列出的反代VPS上，pan/toutiao必须保留。安装器在备份、停服和迁移前预检域名配置、证书、端口和冲突站点。

Ubuntu/Debian、Docker Engine和Compose插件为推荐目标。代码建议放 `/opt/software-showcase`。域名A/AAAA必须指向正确主机；只放必要的80/443公网端口，应用和数据库不对公网映射。

## 安装

1. 复制本目录代码，排除 `.venv/`、`data/`、`test-results/`、`界面预览/`、`.impeccable/`、`.env`、`.git`。已有正式站更新时保留它的`.env`和数据卷。
2. 复制 `.env.example` 为 `.env`，填 `SITE_DOMAIN`、精确 `SITE_HOSTS`、`SITE_CSRF_ORIGINS=https://域名`。用密码学随机数生成至少50字符的 `SITE_SECRET_KEY`，`.env`权限600；之后更新保留同一值。没有卡密/验签密钥。
3. 先准备本站有效证书`/etc/letsencrypt/live/本站域名/`，不改其他站证书；安装器不会代替域名所有者选择DNS。只从`/opt/software-showcase`以root执行`bash deploy/install-site.sh`。它先预检，构建镜像，停止应用并确认停写，用一次性容器备份已有数据库与媒体（即使旧app已停止），备份成功才迁移、收集静态、检查生产配置并启动；最后仅安装本站Nginx配置并重载。只compose up不是完整安装。
4. 执行 `docker compose exec app python manage.py createsuperuser`，交互设置本站管理员。已有站不重置密码。
5. `docker compose ps`查看应用健康；先核对本站回环18082，再以正确Host/SNI核对本机HTTPS，最后从公网验证证书、`/health/`、首页、`/manage/login/`、CSS、图片与图标。不能把其他站或重定向的200当作本站成功。
6. 更新归档保留新资源的当前mtime，避免collectstatic将新文件当旧文件跳过；仍须逐字核对static源码、staticfiles收集产物和公网实际CSS/JS相同。运行部署清单中的真实验收；成功后保存镜像/代码版本、域名、数据卷、备份位置。脚本 `INSTALL_STEPS_OK` 只是步骤完成，不代替人工验收或TLS证明。

应用以UID/GID10001运行，SQLite和图片位于`site_data:/data`，静态资源在`site_static`，证书由宿主Nginx使用。不要执行`docker compose down -v`。单worker/4threads适合小型内容站；高并发/多写入场景先容量验证，不承诺无限规模。

HSTS初始只约束本站主机1小时，不代域名所有者决定子域或浏览器preload。只对这两项明确选择（Django security.W005/W021）记录静默，其他部署安全检查仍作为安装闸。将来确认所有子域策略后可单独调整，不能为了清警告把整个域名送入preload。

## 需要实际验证

匿名无法进后台，登录后才能管理；错误登录被限流；CSRF错误不写数据；创建临时分类与软件→上传两图→排序/封面→存草稿→管理员预览→设置真实测试链接→上架→匿名访问→图片左右箭头与手机滑动→两外链→下架→恢复→回收与恢复。测试后只删除自己创建的测试内容。

对缺失静态、图片、超大上传和权限错误检查反馈。外部售卡页和下载文件可用性由真实目标链接另验。`/image/`不能用静态目录直出，否则会泄漏草稿/下架图。不要把管理目录或data设置为公开目录。
