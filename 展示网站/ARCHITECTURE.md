# 架构与边界

独立 Django 单体。`showcase/` 仅负责本站配置与路由，`catalog/` 负责内容、登录和业务，`templates/` + `static/` 是完整前后台，不依赖授权系统、第三方前端构建或远程CDN。

访客请求 `/` → 读取已上架、未进回收站、分类可见的软件 → 服务端分页/搜索 → 完整图文。`/go/<id>/download/` 和 `purchase/` 只读取本站管理员保存的HTTP(S)链接，不接受访客指定跳转地址。下载是跳转到文件服务器，不是本站存储/安装软件包。

管理端 `/manage/` 使用本站 staff 账号、Django session 和 CSRF。站点未提供公开注册。表单同步提交，失败保留文字/链接；浏览器不允许重填文件选择，因此校验失败需要重新选择本次尚未保存的新图，已有图不丢。产品与分类/站点更新携带 revision，拒绝旧页面覆盖；涉及图片的元数据在事务内保存。图片先校验后重新编码为WebP，随机名存盘，不保留原文件名/EXIF/SVG/动图。每款最多12图，单图8MB、1600万像素，输出最大2560边长。

`Product` 的状态与删除分开。回收只隐藏，恢复为草稿，图片和链接保留。`Category` 删除使用保护外键；已有软件必须选新分类，包括回收站软件。隐藏分类会同时隐藏下属商品，不改软件自身状态。

`ProductImage` 以排序和封面标记展示。图片通过权限受控视图读取，不开放整个媒体目录；草稿/下架/回收图片仅管理员可读。媒体移除只删除数据库引用，磁盘暂保留，避免事务回滚和备份并发导致文件丢失；不自动清理孤立图。

单人内容站采用SQLite（忙等待20秒）。站点数据、图片、本地独立session密钥都在 `data/` 或显式 `SITE_DATA_DIR`，不入Git。正式环境必须设置独立长 `SITE_SECRET_KEY`、明确域名、HTTPS；不是卡密加密/验签密钥，不接触授权平台钥匙包。禁止把演示数据自动带进生产。

登录尝试通过数据库固定15分钟窗口记数，来源和账号两类预算，每类30次，包括成功尝试。默认只认直连peer，不信任访客X-Forwarded-For；官方单入口代理部署会令全部后台登录共用一个来源桶，对小型单管理员站是保守上限。数据库预算不是公网抗DDoS设施。

前台无SPA，分类/搜索/页码写URL；浏览器前进后退和返回购卡页面可恢复原页面。图片库和管理端排序用原生JS渐进增强；服务器再次验证文件、归属、顺序与封面，不信任DOM值。
