# 域名、证书和流量边界

不要把本文件当成装机步骤。本页说明接线关系；实际创建证书、更新Nginx与重建应用都只由 [08](08-完整部署SOP.md) 的install-site.sh完成，不在这里维护第二套安装命令。

现行授权域名是 `auth.example.com`，位于192.0.2.10，服务器身份见 [服务器表](09-两台VPS.md)。直链和展示分别为files.example.com、showcase.example.com。换域名先确认DNS指向目标主机，目标域名须在既有production.env的ALLOWED_HOSTS及CSRF_TRUSTED_ORIGINS中，由维护者按已授权范围受控调整；平台加密/验签密钥保持不变。

```text
浏览器/授权A → HTTPS目标域名:443 → Nginx
  ├─ 明确的冻结HTML/静态资源 → 主机 docs/ui-preview/
  └─ /api/、/healthz/ → 主机127.0.0.1:18002 → 容器0.0.0.0:8000
```

根路径必须404，不跳转/泄漏管理入口；应用宿主端口不公开，HTTP由正式HTTPS策略处理。Nginx需保留120m上传限制及600秒代理读超时。网站证书在 `/etc/letsencrypt/live/<目标域名>/`，由certbot续期；MinIO内部TLS使用自己的CA和证书，两者均不是卡密密钥。

健康核对使用 `https://auth.example.com/healthz/`。旧legacy.example.com仍经192.0.2.11的受验证TLS反代访问同一新平台；目标只信任该固定旧源IP传入原客户端地址，不信任任意公网请求的同名头。旧源保留原证书续期，不再恢复第二套写业务应用。内部HTTP受HTTPS重定向与Host校验影响，不能把内部301误判成公开站不可用。

实际配置源是 `deploy/nginx/authorization-platform.conf.example`。本目录nginx下退役域名文件是回归夹具，不能作为当前站点接线来源。证书到期预检和续期失败告警的实机能力须另验，定时器存在不等于告警已送达。
