# GitHub加密备份副本

GitHub是本机加密.enc之外的可选副本，不是唯一恢复位置。正式备份页仓库使用 `gthubtom1/authorization-platform-backup-prod`；令牌等材料按钥匙包README索引查取，不放进Git、日志或软件接入JSON。旧库名 `authorization-platform-backup-test` 仅用于历史识别，不作为当前备份目的地。安装器 **不准** 打开总开关，也不关闭已有开关。

## 页面与实际runner

负责人在备份页保存总开关、定时计划、GitHub仓库和令牌；安装器保留已有开关。备份先写本机加密包，再按配置拷GitHub；不开GitHub仍可完成本机导出。推送成功不等于已做独立远端读回或隔离恢复。

当前备份runner将页面保留数量限制在1—3范围后清理导出文件。`github_collapse.sh`另有默认KEEP=3；runner只透传仓库名，没有将页面保留值透传KEEP，所以两者目前不能宣称始终同口径。该差异和边界风险保留在STATUS，本次不改脚本。

## 自动历史折叠的边界

仅删除工作树旧.enc不会回收Git历史对象。runner推送成功后自动调用collapse，在达到阈值时折叠备份库历史，并保留受控pre-collapse引用。它操作的是备份页指定仓库，不是本平台源码仓库。

不在本页提供人工强推、删分支或gc步骤，避免把自动机制说明变成日常操作授权。仓库分支列表不能证明只剩一个提交；本地checkout的rev-list结果也不是远端独立读回证明。需要维护时先确定实际仓库与版本，保留证据，再单独实施。

正常巡检应核对最近运行结果、本机.enc哈希、远端对应包的实际可读性和时间，并定期隔离恢复比对业务清单。仅有开关true、success字样或旧时间戳均不足。安装步骤仍为 [08](08-完整部署SOP.md)。
