# 安全基线

本文是 v1.0 的最低安全要求，不等同于“绝对防破解”承诺。威胁模型包括恶意最终客户、恶意下游、被修改的客户端、重放请求、越权访问和泄露的卡密。

## 信任边界

- 浏览器、下游和最终客户客户端都视为不可信输入方。
- 服务端数据库、额度流水、授权状态和撤销记录是事实源。
- 客户端可以被反编译或修改；重要业务逻辑不能只放在客户端。
- 每个软件的授权 A 是中央平台的公共 API 调用方和核心 EXE 的本地桥接方；授权 A、核心 EXE 和中央平台都不互相共享管理员凭据。
- 核心 EXE 只能连接同一软件授权 A 的本机接口；中央平台不主动连接授权 A 或核心 EXE，核心 EXE 不直连中央平台。
- IP、硬件指纹和 Device ID 只能作为风控信号，不能单独作为身份凭证。授权 A 的 `installation_id` 取值必须是稳定主板/硬件指纹且重装不得换值，但仍须经 `device_proof`，不能单靠裸指纹放行。
- `software_id`、`profile_id`、`client_id`、`target`、`arch` 和 `channel` 都来自不可信客户端，服务端必须与登记 Profile 严格比对；不能因为“像是同一个软件”而放行。
- 客户端不能自行声明可信公网 IP；服务端从 TCP 对端和明确配置的可信反向代理解析来源，不能盲信任任意 `X-Forwarded-For`。

## 身份和权限

- 管理员与下游使用不同权限范围。
- 默认拒绝，按“身份 + 对象归属 + 动作”授权。
- 所有下游查询都从会话身份推导 `downstream_id`，不信任隐藏字段。
- 管理员账号使用强密码、登录限速、会话失效和 MFA 预留能力。
- 管理员和 active 下游可以在已登录会话内自助改密；管理员可以按单个未归档下游重置密码。两条路径都必须有 CSRF、密码专用限速、持久幂等键、失败/成功审计和会话失效，不提供明文密码查看或应用内密码回显。
- 邀请码未使用前没有业务到期时间，也不因失败尝试耗尽而作废；必须使用共享限流、临时冷却、一次性原子消费和管理员撤销能力。历史旧 TTL 已到期且未使用的邀请码保持作废。
- 密码使用成熟密码哈希，不能明文保存或写入日志。
- 注册、登录、邀请码生成和邀请码消费必须限速；失败提示不能确认用户名或邀请码是否存在。
- 下游对象权限必须由服务端从会话身份推导；隐藏字段、URL ID 和客户端角色声明都不可信。
- 登出响应永不返回隐藏入口 `entry.html`；管理员落到管理登录页，下游和匿名会话落到下游登录页。管理端/下游工作台、登录页和 `preview.js` 都不得出现 `entry.html` 字面量；需要入口时只能手输受控路径。
- 下游设备查询和重置必须从当前会话推导卡密归属；设备操作引用同时绑定下游、授权和设备，不能把管理员的全平台处置接口下沉给下游。
- 活跃下游只能先归档再删除；删除前写脱敏墓碑，避免历史引用变成无主数据。
- 完整邀请码响应必须使用 `Cache-Control: no-store`；生成页面使用一次性提交令牌和 PRG，危险删除必须二次确认。

## 卡密和密钥

- 卡密和额度卡使用密码学安全随机数生成，禁止递增或可预测规则。
- 数据库保存哈希用于查询；需要再次导出的明文必须加密保存。
- 完整卡密只在必要操作中显示。显示、复制和下载完整码**不**写“谁看过”审计（ADR-0010 产品冻结）。生成、兑换、作废、回收、撤销仍写审计。日志、URL、隐藏 DOM 禁止明文完整码。残留风险：无法从审计还原谁复制了某枚码。
- 授权卡密生成结果和再次查看都必须按当前下游归属授权；再次查看使用 POST、`no-store` 和独立限速，数据库只保存 HMAC 查询值与独立密钥版本的密文。
- 卡密加密必须使用独立的 `LICENSE_CARD_ENCRYPTION_KEY`；生产缺失时启动 fail closed，不得回退到邀请码密钥。历史 v1 数据只能通过显式 `LICENSE_CARD_LEGACY_ENCRYPTION_KEY` 兼容读取，轮换后必须有迁移/恢复演练和密钥托管证据。
- 额度兑换码同样必须使用独立的 `QUOTA_CARD_ENCRYPTION_KEY`，不能回退到邀请码密钥或通用凭据密钥；历史 `v1` 只能通过显式 `QUOTA_CARD_LEGACY_ENCRYPTION_KEY` 读取。轮换默认只读校验，应用迁移必须有明确开关、事务回滚和隔离恢复证据。
- 客户端不能包含管理员密钥、数据库密码或平台对称主密钥。
- 授权 A 也不能包含管理员密钥、数据库密码或平台主密钥；它只能使用公共客户端合同、设备证明和短期会话材料。
- 私钥来自环境变量或受管密钥服务，不写入源码、样例、测试快照和文档。
- 平台响应验签公钥只由受控管理员会话从 `/api/v1/manage/authorization-signing-key/` 导出；匿名 Manifest 和公共授权端点不提供公钥信任根。导出只包含 `key_id`、Ed25519 公钥及其公开编码元数据，使用 `no-store` 并写不含公钥值的审计；私钥、种子、环境变量和密钥托管定位符永不导出。
- 日志、异常、截图和导出文件必须脱敏密码、Token、卡密和设备私钥。
- `PasswordOperation` 只保存脱敏目标、服务端 HMAC 请求摘要和可重放的脱敏响应；模型层拒绝修改/删除。请求 HMAC 使用独立的 `PASSWORD_OPERATION_HASH_KEY`，生产缺失时启动 fail closed，不得用裸 SHA-256 保存含密码的请求摘要。
- `DownstreamAdminOperation` 只保存管理员/目标摘要、动作、服务端 HMAC 请求摘要和脱敏响应；创建下游时即使请求哈希覆盖初始密码，也不得保存密码原文。业务状态变化和幂等事实必须在同一事务中提交。

- 管理端和下游端的授权/设备读侧按权限返回客户端设备码 `installation_id`、平台设备 UUID、IP、用户名和业务对象引用；客户端设备码用于客服核对与搜索，平台 UUID 仍是内部操作标识。卡密、额度兑换码、密码、Token、设备私钥和安装 hash 仍按敏感凭证规则保护。设备处置继续使用短期、绑定授权范围的加密 `device_action_ref`（不能从票面还原 UUID），该操作引用不是展示用设备 ID。

登录限流与认证统一使用 NFKC、去空白及大小写折叠后的用户名；登录另有按入口/来源地址的总预算，注册另有不依赖提交邀请码的来源地址总预算。API与保留登录/注册入口共享预算。固定窗口计数必须原子更新，竞争或缓存故障不得默认放行，不提高原有限额。

## 公共授权 API

- 全部使用 HTTPS。
- `/api/v1/` 的实际调用方是对应软件的授权 A；核心 EXE 的网络配置、日志和依赖中不得出现中央平台直连入口。
- 激活、验证和解绑使用一次性 nonce 防重放，并结合 Ed25519 设备公钥证明；服务端只保存 nonce 哈希，重用 nonce 返回 `REPLAY_DETECTED`。
- 服务端重新验证软件、卡密、套餐、下游账号状态、设备限制、版本和风控。unused 首次激活另查该下游该软件经营范围必须为 `ACTIVE`（无行/`CLOSED` 都拒）；这不是把账号暂停扩大到经营范围。账号暂停仍用 `DOWNSTREAM_NOT_ACTIVE` 拦新激活和换机。
- 服务端只返回当前软件/Profile 的类型化能力和 Entitlement；能力键必须登记、带范围并按命名空间隔离，不能下发可执行脚本。
- 激活、验证、兑换、登录、导出和邀请码接口必须限速。
- 公共授权 API 按动作和服务端解析的来源地址限速；限速返回 `429/RATE_LIMITED`、`Retry-After`、`no-store`。`verify` 必须先做授权判定：硬失败（`DEVICE_NOT_BOUND`、撤销、阻断、到期、设备密钥无效等）原样返回，禁止先 429。`RATE_LIMITED` 只用于绑定仍有效、问太勤。`activate` / `deactivate` 仍在判定前限流。被拒绝的 `verify` 另计失败观察预算（按来源地址、独立窗口），只用于观察，不得因预算耗尽把硬失败替换成 429。成功请求不计入该预算，所以持续正常的客户端永远不会被它挡住。本地默认可用 `LocMemCache`，生产配置会拒绝它并要求共享后端；当前实现支持 Django `DatabaseCache`，部署前必须先执行 `manage.py createcachetable` 并在接近目标 Worker 数量的环境复测限流和幂等。`allow()` 必须保住本次传入的窗口：Django 5 的 `DatabaseCache.incr` 等于 `get` + 不带 timeout 的 `set`，会把 TTL 改成 `DJANGO_CACHE_TIMEOUT`（默认 300 秒）；实现不得靠这次 incr 续期。窗口过了必须从 1 重算。不要改成全站一个池，也不要把加大次数当成修复。
- 错误信息不区分“卡密不存在”和“卡密存在但不属于当前软件”到足以被枚举的程度。
- 公共授权请求体在 `json.loads` 之前先按 `CONTENT_LENGTH` 与实测长度双重限制（32KB），并拒绝过深嵌套；输入字符串在规范化阶段拒绝含孤立代理码点的值，避免 `UnicodeEncodeError` 变成未捕获的 500。
- 授权响应强制使用精确小写 `ed25519` + `JCS-RFC8785`；未知 key/算法/规范化/签名错误 fail closed。对象键按 **UTF-16 码元序**排序（RFC 8785），不是 Python 的码点序——两者在键含辅助平面字符时结果相反，按码点序会让严格实现 JCS 的客户端验签失败。响应有有效期和服务端时间；缓存宽限不覆盖撤销和封禁。
- 同一请求重试必须幂等，不能重复扣款、返还、激活或兑换。授权激活/验证/解绑的幂等窗口 = 授权请求记录保留期（默认 30 天，`AUTHORIZATION_REQUEST_RECORD_RETENTION_DAYS`）：窗口内同 key 重试返回原结果，超期后原结果已按保留期清理，同 key 重试按 `REPLAY_DETECTED` 拒绝（客户端须换新的 request_id/idempotency_key/nonce）。额度与卡密类幂等不受这个窗口影响。
- 激活/验证/解绑保存请求指纹和响应；同一 `action + Idempotency-Key` 只能对应同一请求体，换请求体返回 `IDEMPOTENCY_CONFLICT`。
- 授权卡密内部生成分组的总成本、随机卡密碰撞、幂等和外层事务失败必须可审计且不能留下孤立额度扣除；分组不得成为用户页面的批次事实。

## 授权 A、本地接口和缓存

- 授权 A 到核心的本地接口默认只绑定 `127.0.0.1`，使用随机端口、短期本地会话令牌和软件/Profile/客户端版本校验；不得监听 `0.0.0.0` 或把端口暴露到公网。
- 本地响应只允许版本化 JSON/IPC 数据：授权状态、服务端时间、到期时间、能力、联系方式、公告、更新元数据和配置版本。禁止任意脚本、命令、DLL 路径或动态代码下发。
- A 层缓存至少按 `software_id`、`profile_id`、`authorization_id`、设备范围和 `config_version` 隔离；不能使用明文卡密作为缓存键，不能跨软件、Profile、客户或授权实例复用。
- 缓存不是事实源。配置版本变化、授权撤销、封禁、过期、Profile 归档或本地会话失效时，A 必须刷新/删除对应缓存；安全撤销不能被离线宽限覆盖。
- 核心收到 A 不可用、身份不匹配、签名无效、过期或撤销结果时必须 fail closed；调回本机时间、重启或重放旧本地响应不能恢复受保护功能。
- 授权 A 页面和核心 UI 对 `purchase_url`、QQ、微信、公告等内容做长度、协议、纯文本/安全转义和空值校验；没有配置时隐藏区域，不显示伪造联系方式。

## 时间与反绕过

- 激活对已有授权进行时间回拨持久阻断前，必须先校验设备证明；持有卡密但证明无效的请求不能借服务端时间异常冻结客户。合法证明遇真实回拨仍拒绝。后台只读标记区分时间阻断与普通冻卡，管理员核对服务器时间后可走现有恢复服务；不得把服务端时间回拨描述成客户作弊。
- 应用以服务端 UTC 当前时间比较有效期；VPS 设置为 UTC、北京时间或其他时区都不能改变同一个时间瞬间的授权结果。
- 生产主机必须保持系统时钟同步；应用代码不能使用无时区的本地时间或把本机时区当作业务规则。
- 客户端本机时间、时区、手工提交的 `expires_at` 和缓存中的旧时间都属于不可信输入；客户端改回时间、跨时区或重启不能延长授权。
- 授权响应必须带以有符号 64 位 Unix epoch seconds 表示的 `server_time` 和 `expires_at`。客户端应使用单调计时做本地展示，并在验证/心跳或重新启动时按服务端结果决定是否锁定；发现时间回退时返回不可重试的 `TIME_ROLLBACK_DETECTED`，服务端拒绝后客户端必须 fail closed。
- 1 分钟测试卡必须覆盖“到期前成功、到期后失败、调回本机时间仍失败、重启后不能绕过”的负向测试。
- 平台服务端按卡密 → 授权实例 → 设备 → 设备密钥 → 当前绑定的顺序锁定资源；设备上限检查在授权实例锁内完成。管理员阻断设备时若绑定集合在取得设备锁前后发生变化，事务必须回滚并有限重试，不能漏掉新绑定。SQLite 只用于本地行为测试，PostgreSQL 行锁并发必须在上线前单独验证。

## 输入、文件和链接

- 所有输入校验类型、长度、格式、范围和对象归属。
- 防止 SQL、模板、HTML、命令、路径和 CSV 公式注入。
- 二维码、图标和安装包限制大小、类型、扩展名和存储位置。
- 发卡网地址只允许 `https`（必要时明确允许 `http`），拒绝 `javascript:`、`data:` 和不受控跳转。
- 文件下载使用访问控制或短期 URL，不能暴露服务器路径。
- 公告、联系方式和更新说明按纯文本展示或经过安全转义。

## 审计和隐私

关键事件至少记录：时间、操作者、角色、IP、请求 ID、软件、下游、对象、动作、前状态、后状态、结果、原因和来源。客户端可控的授权 request_id 在授权审计中使用稳定摘要；管理员风险页面只显示摘要，不能把客户端自定义值当作安全凭证或明文秘密展示。

审计记录不能由普通后台操作删除或覆盖。高频验证可做聚合日志，但激活、撤销、回收、额度变化、登录失败和越权尝试必须保留明细。管理员风险动作的原因和生效时间必须进入不可变审计元数据；待复核信号只提示人工，不因单次普通失败自动封禁。密码修改/重置成功、失败和限速都保留 `auth.password_change`/`auth.password_reset` 明细；metadata 只允许目标摘要、操作 ID、幂等键摘要、原因长度/摘要和稳定错误码，禁止密码、确认密码、原因原文和完整请求体。

未激活卡回收和管理员额度回收必须使用服务端锁与幂等键；回收失败不能改变卡密状态或余额，成功记录前后状态/余额、原因、来源和操作者，不记录完整卡密。

卡密生命周期和审计事件由模型层拒绝普通 ORM 更新/删除；只有明确的领域服务或内部迁移动作可以带受控的变更标记。零成本卡仍必须完成不可恢复状态转换，但不伪造额度流水。

设备码、设备 UUID、IP、联系方式、二维码和日志属于敏感运营数据，应明确用途、保留期限和访问范围；授权/设备读侧按权限明文展示客户端设备码与设备 UUID/IP，卡密/额度码、密码、Token、私钥和安装 hash 仍不得明文泄露。客户端设备码不得写入公共授权响应、通用日志或未授权下游结果。

## 更新和供应链

- SHA-256 只用于检测内容变化，不能单独证明安装包来源。
- 发布包应支持数字签名和签名密钥轮换；私钥不放在应用仓库。
- 上传包必须限制大小、读取唯一 `client-release.v1` Manifest、服务端重新计算大小/完整包 SHA-256，并校验软件/Profile/平台/架构/通道；生产 Manifest 还必须包含纳入签名覆盖范围的 `payload_sha256`，`declared` 签名状态不能伪装成 `verified`。
- 公共 registry/download 只允许 active/testing 软件和 Profile；下载前重新解析并检查 release root、普通文件和符号链接，越界或篡改包必须拒绝。清理作业删除前重新校验路径、大小和已记录哈希，不能把清理当作业务删除。
- 备份下载只允许管理员从 `BACKUP_DOWNLOAD_DIR` 获取加密 `.enc` 普通文件；服务端拒绝路径穿越、软链接和明文扩展名，响应不缓存，审计不记录口令或完整文件内容。GitHub 凭据使用独立密文保存，管理 API 不得回显。恢复口令只用于当次核对/导入，不得入库、不得写入日志或审计。
- 管理端导入恢复必须先核对比京时间；只有当前没有软件、下游、卡密、额度账本和下游墓碑时才能把备份写入数据库。**判空必须是全库口径**：除安装脚本自己创建的管理员账号、平台自身的审计行、备份排队/策略/暂存这几类（F-023 明确定为不阻塞）之外，任何应用模型有行都算非空——只数十张业务表会让「只有设备、只有发版、只有批次或生命周期操作记录」的库被当成空站，随后 `pg_restore --clean` 把这些行静默丢弃。管理员和当次核对自己写的审计不算非空。已有业务数据时拒绝导入，避免覆盖正在运行的站点。
- 判空与 `pg_restore` 之间必须持有跨进程排除锁（PostgreSQL session 级 advisory lock），并在真正执行前再判一次空。判空所在事务必须在 `pg_restore` 之前提交，没有这道闸门时其它 Worker 在窗口期写入的业务行会被 `--clean` 丢弃。
- 换机恢复必须使用导出备份当时的卡密加密密钥与 Django SECRET，不得为已有客户新生成一套密钥后再导入 dump。运维说明只在 `部署与恢复/`。当前测试数据不是客户恢复点。平台密钥已定死为钥匙包中的一套（ADR-0015），测试站与正式站不得另做一套。
- 公共 Release **本站 ZIP** 谁都能下，不要求卡密；按 IP 限流。默认客户更新打开 `external_download_url`。不要把卡密放进网址，不要给 `/api/` 加 CORS `*`。安装包被人拿到不等于能进主程序。
- 更新请求由授权 A 代为获取；核心只接收已验证的类型化更新状态。默认更新打开受控网盘地址；采用本站包或自更新通道时，下载包须校验相应哈希/签名。不能把平台URL、命令或脚本直接交给核心执行。
- 版本发布、强制更新、最低版本和回滚都必须审计。
- 第三方依赖固定版本，记录许可证和替换方案。
- 不直接执行外部仓库的安装脚本或二进制文件。

## 数据保护和恢复

- 数据库、对象存储和备份分离权限。
- 备份必须通过本机加密 `.enc`（可选再拷 GitHub）；备份账号不得复用应用发布包账号。**现行 Docker 部署不用 pgBackRest，也不要再去装双仓 WAL。** 旧模板里的 pgBackRest 不是还欠的活。
- 生产密钥、PostgreSQL、签名强制仍 fail closed。对象存储证明若启用，必须列出对象存储键；扫描数据库数据目录不能当作对象清单成功。现行备份默认不拷安装包。
- 恢复后必须核对逐账户额度流水链与余额、未使用/已兑换/已回收/已撤销卡密状态、密文与密钥版本、授权实例、设备/密钥/绑定历史、软件/Profile/能力/套餐/经营范围、版本包元数据、审计时间线和所有持久化操作/幂等记录；数据库清单必须来自一致性读取快照。
- `recovery_inventory --verify-ciphertext` 只能在内存中解密并重新核对 HMAC；恢复清单、日志和告警不得包含密码、完整卡密、令牌、私钥或备份口令。
- GitHub 私密库只能保存加密恢复清单/索引和运行收据，不能保存明文 dump、`.env` 或密钥，也不能作为唯一灾备位置。
- 生产迁移、密钥轮换、部署和远程发布必须由用户明确授权。

## 生产配置门

门禁分两档：`APP_ENV=local` 之外的一切（含 `test` 测试授权平台）都要过下面的**非本地门**；`production` 再加对象存储、备份合同和生产 Worker 数。这是为了让 `APP_ENV=test` 不会因为「不是 production」而绕开密钥与限流要求。

- 非本地（`test` / `production`）必须同时使用 PostgreSQL、显式数据库连接参数、长随机 `DJANGO_SECRET_KEY`、独立 `PASSWORD_OPERATION_HASH_KEY`/`ACCOUNT_OPERATION_HASH_KEY`、独立 `QUOTA_CARD_HASH_KEY`/`LICENSE_CARD_HASH_KEY`/`QUOTA_CARD_ENCRYPTION_KEY`、独立卡密加密密钥、授权 nonce/device HMAC 密钥和 HTTPS 的 `CSRF_TRUSTED_ORIGINS`；缺任一项应用启动即失败。
- `DJANGO_SECRET_KEY` 不接受 `deploy/production.env.example` 里的 `replace-with-…` 占位符，也不接受「长度够但字符类单一或重复」的值：session 签名与多个派生密钥都建立在它之上。检查同时覆盖字符类数量与去重字符数，错误只报告配置名、不报告值。
- 非本地必须配置独立的 `INVITATION_ENCRYPTION_KEY`、`QUOTA_REDEEM_IP_HASH_KEY`、`AUTHORIZATION_SIGNING_PRIVATE_KEY`、托管的非开发 `AUTHORIZATION_SIGNING_KEY_ID`、`RELEASE_SIGNING_KEY_ID` 和有效 `RELEASE_SIGNING_PUBLIC_KEY`，并强制 `RELEASE_REQUIRE_VERIFIED_SIGNATURE=true`；环境变量显式关闭签名强制时启动失败。`AUTHORIZATION_SIGNING_PRIVATE_KEY` 为空时**只有 `APP_ENV=local` 允许**由 `SECRET_KEY` 派生调试私钥；`test` 与 `production` 都直接拒绝启动，避免用公开常量推出可伪造授权响应的私钥。
- 非本地 `DJANGO_DEBUG` 必须为 false（含 `test`）。
- 非本地本站安装包下载不得再强制卡密（`RELEASE_DOWNLOAD_REQUIRE_AUTH=true` 时启动失败）。同样拒绝把 `PUBLIC_LICENSE_RATE_LIMIT`、`PUBLIC_RELEASE_DOWNLOAD_RATE_LIMIT` 或 `PUBLIC_RELEASE_DOWNLOAD_IP_RATE_LIMIT` 设为 0 或负数。
- `AUTH_LOGIN_RATE_LIMIT`、`AUTH_REGISTER_RATE_LIMIT`、`AUTH_PASSWORD_CHANGE_RATE_LIMIT`、`AUTH_PASSWORD_RESET_RATE_LIMIT` 非本地必须为正；`AUTH_RATE_LIMIT_WINDOW_SECONDS` 不得小于 10 秒。把这几个设成 0 或 1 秒等于静默关掉爆破防护。
- 所有非本地密钥彼此独立，不能复用 `DJANGO_SECRET_KEY`，错误只报告配置名，不报告值。
- `ALLOWED_HOSTS` 不接受 `*`、localhost、loopback 或 `0.0.0.0`；`SECURE_SSL_REDIRECT`、Cookie Secure、HSTS 和 `SECURE_PROXY_SSL_HEADER` 只按明确配置生效。
- 非本地必须显式配置 `TRUSTED_PROXY_IPS`（不依赖 `TRUST_PROXY_SSL_HEADER` 是否打开）。只有该网段内的直接对端可以提供 `X-Forwarded-For`/`X-Forwarded-Proto`；不在网段内的请求会清除这些头。若整条转发链（含直接对端）都落在受信网段内，服务端回落到实际观测到的对端地址，**不采用请求方自选的 `X-Forwarded-For` 首项**，否则调用方可以自选限流身份。
- 非本地共享限流/短期幂等缓存只能用白名单后端（`DatabaseCache`、Redis、memcached）；`LocMemCache`（进程内、跨 Worker 不共享）和 `DummyCache`（`add` 恒真、`get` 恒空，会让所有限流恒放行）都在启动时拒绝。配置变更和迁移必须在备份、回滚和真实运行验收证据齐全后执行。
- 共享缓存必须显式设置 `OPTIONS.MAX_ENTRIES`，且远大于预期并发身份数。Django `DatabaseCache` 默认上限是 300，超过后 `_cull` 会**按 cache_key 顺序删除尚未过期的行**；默认值下调用方只要制造足够多的无关 key，就能把自己的限流桶一并清空。
- 密码修改与重置限速使用 `AUTH_PASSWORD_CHANGE_RATE_LIMIT`、`AUTH_PASSWORD_RESET_RATE_LIMIT` 和共享缓存窗口；生产多 Worker 必须验证同一账号跨进程仍受同一限额约束。
- 生产 Worker 数量必须至少为 2，限流/幂等缓存必须是跨进程共享后端；B7.2 的 `shared_rate_limit_probe.py` 在批准的 loopback 隔离 PostgreSQL 中以 2 个进程真实调用 `rate_limit.allow()`，正控要求同一身份 1 次允许/1 次拒绝，负控要求两个不同身份都允许。旧 `shared_worker_probe.py` 的 `DatabaseCache.incr` 计数器仅作诊断，不能作为发布证据，因为该实现不是原子自增，而且会把 TTL 改成缓存默认超时。限流窗口测试必须用 `DatabaseCache`，不能只拿 `LocMemCache` 绿。
- 生产对象存储必须显式使用 `s3` 或 `s3-compatible` provider，并注入 endpoint、bucket、region、access key 和 secret；`OBJECT_STORAGE_PROVIDER=local` 只允许本地测试，不能作为生产回退。
- 兼容启动声明门：settings仍要求BACKUP_PROVIDER=pgbackrest、双仓库/故障域、加密/TLS、WAL、保留/RPO/RTO与告警配置等声明，缺失仍拒绝生产启动。本次不放宽该门；实际Docker runner是完整加密dump，health按dump_only标明严格proof缺口。配置校验通过不能证明PITR/双仓/异地恢复或告警投递已运行。实际安装按根部署08，不另装旧候选设施来迎合文档。

## 必须通过的安全测试

1. 下游 A 修改 ID 不能读取下游 B 的卡密、设备、流水或日志。
2. 同一额度卡、卡密回收和生成请求并发执行不会重复生效。
3. 重放激活请求不能增加设备或延长授权。
4. 修改客户端提交的到期时间、软件 ID 或下游 ID不会改变服务端结果。
5. 撤销、封禁和关闭在缓存规则内按预期失效。
6. 日志和导出中不出现完整秘密凭证。
7. 恶意 URL、文件和公告内容不会执行脚本或访问内部路径。
8. 软件 A 的身份伪造、能力键伪造或适配器异常不会改变软件 B 的余额、卡密、设备、会话或审计。
9. 客户端修改本机时间、时区或提交伪造 `expires_at`，不能延长已到期授权。
10. 同一邀请码并发注册最多一个成功，失败注册不创建 User/Profile、不消费邀请码。
11. 下游 A 修改 URL/表单中的下游 ID 不能读取或修改下游 B 的数据。
12. `suspended`/`closed` 下游无法登录；激活对象未归档时删除被拒绝。
13. 自助改密只能作用于当前会话，管理员重置只能作用于指定未归档下游；密码请求重放不重复改变密码或会话版本。
14. 密码操作审计、响应、URL、日志和导出中不出现密码或原因原文；密码操作记录不可修改、不可物理删除。
15. 备份/恢复和运维 marker 中不出现密码、完整卡密、令牌、私钥、数据库连接值或备份加密口令；备份失败、marker 过期、WAL 停止和磁盘严重不足必须能被外部观察者发现。
16. S3/兼容对象存储启用时，本地 `storage/tmp/`、`storage/exports/`、`storage/logs/` 仍必须进入受控清理范围；清理不得删除审计、额度流水、卡密、授权实例、设备和账号事实。
18. 恢复清单必须逐账户验证 `balance_before → balance_after` 链和最终余额，不能只比较全局 credit/debit 总和；卡密密文/HMAC/密钥版本任一不匹配都必须 fail closed。
19. 恢复判空必须覆盖全库：只有设备、只有发版、只有批次或生命周期操作记录的站点都要被判为非空并拒绝导入。
20. 非本地环境不得用示例占位符或低熵值启动；`test` 环境不得由公开常量派生授权签名私钥。
21. 共享缓存的 `MAX_ENTRIES` 必须显式设置，制造无关缓存键不能清空限流计数。
22. 公开授权接口必须拒绝超大请求体、过深嵌套和含孤立代理码点的字符串，且都以 400 结构化错误返回，不产生 500。
23. 被拒绝的 `verify` 仍受失败预算约束；预算耗尽返回 429，成功请求不计入预算。
24. 发布 ZIP 必须拒绝盘符前缀与符号链接条目，客户解压不得越界写盘。
25. 核心 EXE 不直连中央平台，只有对应授权 A 访问 `/api/v1/`；伪造或替换授权 A 的本地身份时核心拒绝。
26. 软件 A 的授权 A 不能读取软件 B 的缓存、LocalBroker、授权结果或更新元数据。
27. 下游 A 配置的联系方式/购买链接只出现在其真实归属授权中；下游 B 和无配置客户不看到 A 的值。
28. 客户覆盖优先级、空配置隐藏、配置版本刷新和授权撤销后的缓存失效均按领域规则生效。
29. 服务端时钟回拨阻断的授权必须能被管理员恢复（解冻即恢复被回拨打断的座位），不能只剩「撤销废卡」一条路。
