# ADR-0007：Django User 凭据与独立 DownstreamProfile

- 状态：accepted
- 日期：2026-08-19
- 领域：账号、权限、租户隔离、迁移

## 决定

PR-02 使用 Django 内置 User 保存用户名、密码哈希、激活状态和会话认证；使用一对一 `DownstreamProfile` 保存下游业务状态、公开 UUID、注册/登录时间和归档信息。管理员使用受保护角色组和 Django 管理属性识别，下游必须同时具备下游角色组和 active Profile。

邀请码、注册、归档和删除通过应用服务完成，不开放直接 ORM 写入口。下游对象的可见范围由当前会话推导，客户端不能提交租户 ID 扩权。删除前写脱敏墓碑。

## 原因

- PR-01 已使用 Django 内置认证；继续沿用可以保留成熟密码哈希、会话、CSRF 和迁移路径，避免现在切换自定义 User 带来的高成本迁移。
- 业务字段与认证字段分离，后续可以独立扩展下游额度、软件关系和审计，不污染 User 表。
- 公开 UUID 避免把数据库自增 ID 直接作为租户对象标识。

## 边界

- 当前不做 SSO、多管理员审批或最终客户平台账号。
- 如果未来必须改变登录标识、接入外部身份源或支持多种主体统一登录，先新增 ADR 和迁移方案，不直接替换 User 模型。
