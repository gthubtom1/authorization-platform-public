# Decision: 8123 静态页面入口地图与未来域名后缀路由

## Context

此前项目文档同时出现了 8123 静态 HTML 文件名和未来 Django 页面路由。批准静态页面后，旧文档可能被误读为已经授权接入 Django 或启动 8143。用户已明确确认未来页面使用方式和部署后的基址替换规则。

2026-08-21 用户进一步明确：后端应适配这五个冻结页面，并先按阶段计划推进。该后续决定记录在 ADR-0013；本 ADR 继续只负责入口地图，不再被解释为“永远不能规划或实现后端”。

## Decision

当前冻结的前端页面以 `http://127.0.0.1:8123/` 为本地基址：

- 管理端工作台：`manage.html`
- 管理端未登录：`manage-login.html`
- 下游工作台：`downstream.html`
- 下游未登录：`downstream-login.html`
- 下游未注册：`downstream-register.html`

部署时，将 `http://127.0.0.1:8123/` 替换为正式域名，后缀继续区分页面。根路径是基址占位，不自动变成管理端工作台。

这些是 8123 静态前端合同，不是 Django URL 合同。静态页面本身不会自动启动真实 Django、不创建 8143 页面、不自动恢复旧 PR；B0—B7是首次接线的历史阶段映射，现行后端已部署，新增需求按STATUS及API合同实施。旧 Django 路径若继续保留，必须明确标记为内部后端路线，不能当成当前前端入口。

## Alternatives

- 将根路径固定为管理端工作台：不采用，根路径只作为部署基址，页面后缀负责区分入口。
- 继续使用 `/manage/login/`、`/downstream/login/` 作为静态页面入口：不采用，这些路径只在真实 Django 后端合同中讨论。
- 为静态页面创建新的 8143 服务：不采用，8123 是唯一冻结的静态前端基线。

## Consequences

- 页面验收、截图和产品讨论统一使用 8123 文件后缀。
- 部署时可以替换域名而不改变页面后缀。
- 真实 Django 路由、数据库和后端实现不能从页面文件名自动推导，按现行API合同、任务范围和验收门禁实施，不重启ADR0013历史阶段。
- 后续文档必须同时标明“8123 静态页面”或“真实 Django 后端”，不能只写“管理端入口”造成歧义。

## Status

accepted
