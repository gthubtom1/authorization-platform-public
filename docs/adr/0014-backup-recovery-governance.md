# ADR-0014：备份证明与隔离恢复治理

状态：部分被现行Docker备份方案取代；inventory、密钥/版本绑定和隔离恢复原则继续有效。原决定日期2026-08-23，取代关系更新于2026-11-16。

## 背景与已取代范围

最初候选选择pgBackRest双独立仓库、连续WAL/PITR及严格proof。现场后来采用完整逻辑dump加密.enc、本机保存和可选GitHub副本，安装只按根部署08；不再把原候选设施列为日常必装或待部署任务。逻辑dump不提供连续PITR，也不能仅因字段声明存在而宣称双仓设施运行。

settings仍有validate_backup_environment旧启动声明校验，要求pgbackrest/双仓/WAL等值；实际health另识别dump_only。这个兼容技术债在STATUS保留，本次文档清理不改变设置或安全门。

## 持续有效的决定

1. 数据库事实、已发布安装包对象、原密钥和代码/迁移版本须成套保管；数据库.enc不含对象与密钥。
2. GitHub仅作额外加密副本，不上传明文数据库/密钥，不把它作为唯一恢复来源。运行成功、密文完整性、远端可读与隔离恢复是不同证据。
3. 隔离恢复从一致性快照生成源inventory，并与不同数据库的恢复inventory比较：卡密状态/密文/HMAC/密钥版本、逐账户流水链与余额、授权、设备/绑定、软件/Profile/套餐/下游范围、审计、持久操作与迁移表。同库自比不能算恢复。
4. 严格proof关联同一backup_run_id、源码/迁移图、dump和对象清单、恢复结果与证据哈希；缺证明不伪造marker，dump_only如实提示证明未齐。
5. 旧服务与恢复材料先保留，确认兼容和业务核对后再切流；代码回退不能代替数据恢复。通知投递、目标RPO/RTO和正式隔离恢复须实测，不能用旧候选目标值承诺现行能力。

实际执行方式只在根部署目录，技术语义见DOMAIN-RULES和SECURITY-BASELINE，验证缺口统一见STATUS。
