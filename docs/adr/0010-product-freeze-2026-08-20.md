# ADR-0010：2026-08-20 产品一次冻结

- 状态：accepted
- 日期：2026-08-20
- 领域：邀请码、额度码、发卡权限、完整码显示、未激活回收
- 取代：ADR-0005 中“凭证每次显示/复制/下载都审计”；工作区曾写的“管理员可代发”
- 部分被取代：§5 回收与批次 UI 已被 [ADR-0011](0011-single-card-archive-revenue-and-links.md) 取代（不再提供批次页与「回收本批」）

## 背景

产品负责人按 `docs/PR-DECISIONS.md` 一次书面裁决。未点名的条目采用清单推荐；下列为例外或被再次确认的冲突项。

## 决定

1. **邀请码**：新码未使用不过期、不预绑下游；完整码仅管理员可再显示/复制/下载。历史已过期且从未使用的码保持作废，不恢复。输错密码不废码，用限流防刷。
2. **额度码**：发行不预绑；谁登录兑换进谁的账；未兑不过期，管理员可作废。废除指定下游的旧发行流程。未兑换且曾带目标下游的历史码转为通用码；已兑换记录不改主人。流水可翻页。
3. **发卡**：只有下游能为自己生成授权卡密。管理员不代发、不生成授权卡密；管理端提供全平台卡密总表（查询、完整码搜索、显示、未激活回收）。
4. **完整码**：必须整码搜索。显示/复制/下载完整码**不**写入“谁看过”的审计。生成、兑换、作废、回收、撤销等业务动作仍审计。日志、URL、隐藏 DOM 仍禁止明文完整码。
5. **回收**：可勾选部分未激活卡；也允许对当前筛选中的全部未激活卡执行确认回收（须确认张数与返还额度），不按批次提供入口。已激活不可回收。回收后不可再激活。该条以 ADR-0011 的单码列表决定为准。

## 替代方案

- 管理员代发：否决。发卡只留下游。
- 完整码每次显示写审计：否决。接受无法追溯谁复制了码的残留风险。
- 恢复历史过期邀请码：否决。旧过期码继续废。
- 旧的按批次回收方案：被 ADR-0011 取代。当前只允许单卡勾选或当前筛选全量回收，必须确认影响范围，不提供“回收本批”。

## 代价与回退

- 管理端卡密页从“代发”改为“监管 + 回收”，与当前 Django 仅下游发卡更接近，但要补全平台列表。
- 安全基线不再要求 reveal 审计；客服纠纷时不能从审计还原“谁看过这枚码”。
- 历史过期邀请码不能再注册，下游若仍持有旧码需重发。

回退需新的产品书面否决本 ADR，不能只改页面文案。
