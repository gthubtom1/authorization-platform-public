# ADR 0017: 防脱机盗开、换机防套利、时钟容差、同机公钥自愈与批量管理

- Status: accepted
- Date: 2026-09-24

## Context

在完成卡密续期与版本管理后，对全平台开展对抗性红队审计与日常商业运营推演，发现以下关键缺陷与安全盲区：

1. **断网脱机常驻漏洞**：原有客户端指引强调“网络错误不关软件”，若黑灰产在激活后通过防火墙切断网络，卡密可断网跑满整个生命周期，甚至利用挤机延迟实现“单卡无限裂变多开”。负责人明确指出：软件均为在线联网工具，默认绝不允许脱机运行，断网或无法联网时主程序必须强制停机。
2. **主动解绑绕过换机限额**：由于换机计数仅在“满员挤机”时扣减，攻击者只需先调用 `deactivate` 释放坑位再激活新设备，即可绕过每日换机限额无限次轮换机器，沦为群控租号工具。
3. **服务端时钟微漂移误杀**：原 `_time_rollback_detected` 对服务端时间设置 0 秒容差，VPS 宿主机 NTP 自动微调或容器启动瞬时漂移会直接将正常付费客户判定为回退攻击并永久打入 `BLOCKED` 封禁。
4. **同机重装公钥失配死锁**：客户电脑重装系统、清理目录或重新解压后，本地生成新公钥但硬件指纹不变，再次激活或验证因公钥与现有绑定不匹配被 `DEVICE_KEY_MISMATCH` 永久死锁。
5. **管理纵深不足**：管理端缺乏批量撤销和批量封禁设备能力；列表无直观续期增补痕迹；外链更新下载缺乏可选包 SHA-256 校验和导致潜在供应链劫持真空。

## Decision

### 一、 默认禁止脱机与联网强校验

1. **默认策略 0 宽限**：`PolicyVersion.offline_grace_seconds` 默认为 0。平台在线授权下发的 `cache_until` 与 `next_verify_at` 严格约束心跳周期。
2. **超时强制锁停**：客户端启动器在连续网络故障或无法完成 `verify` 超过 `verify_interval_seconds + offline_grace_seconds`（默认 60 秒）时，必须立即向核心 EXE 下达终止指令，主程序强制关闭核心受保护功能。严禁断网单机常驻。
3. **显式配置脱机例外**：仅当管理员在平台为特定软件策略显式配置了 `offline_grace_seconds > 0` 时，客户端才允许在宽限窗口内暂缓关停。

### 二、 换机套利防护（真实物理设备切换即扣减）

4. **非同台物理设备介入即计入换机**：已激活授权在非首次激活流程中，坑位已满时新设备介入必须校验换机开关并消耗当日换机额度 `device_switch_count`；坑位未满时从未接入的新设备首次填坑不计次，但历史旧设备切回（与最后一次活跃设备不同）仍计次；当日额度耗尽立即拒绝（`DEVICE_SWITCH_LIMIT_REACHED`）。
5. **同物理机重新登录零消耗**：同一台物理设备（`installation_hash` 一致）同钥在解绑后重新激活或登录，不消耗换机次数；同机重装换新公钥走自愈轮换，计 1 次当日额度。

### 三、 服务端时钟微漂移容差

6. **引入 15 秒时钟漂移容限**：定义 `TIME_ROLLBACK_TOLERANCE_SECONDS = 15`。仅当 `max(last_server_time) - now > 15` 秒时才判定为真实的时间回拨篡改；微小 NTP 校准不触发阻断，同时响应时间戳与数据库持久化的高水位线强制使用最大值 `max(last_server_time, now)`，严格保证单调不后退，杜绝步进式时间倒退攻击。

### 四、 同机公钥自愈（消除重装死锁）

7. **同机携带合法凭证重激活更新公钥**：在 `activate_license` 中，若请求来自同一物理设备（`installation_hash` 一致）且通过完整卡密与新公钥的 `device_proof` 验签，当其存在有效绑定但公钥变更时，允许自愈轮换该绑定的公钥为已验证的新公钥，递增授权 revision 使旧凭据失效，消除重装系统后的死锁，并记录审计日志。

### 五、 批量管理与运维增强

8. **批量撤销、批量封禁与批量解封**：新增管理端批量撤销授权、真正批量封禁物理设备硬件黑名单（`device.risk_state = blocked`）与批量解封（`risk_state` 回 `normal`，旧座位不复活，需新卡重激活）API，多设备卡全覆盖，支持多选、幂等提交、逐条汇报与审计；无活跃绑定的封禁请求与无被封绑定的解封请求一律跳过，不追溯历史。
9. **续期轨迹直观展示**：在授权列表及详情中，若授权被续期过，显式展示“已续期”标记及累计增加的天数/小时数；批量续期弹窗具备防御性过滤，自动剔除已失效卡。
10. **外链更新完整性防投毒**：发布与修改外链时支持可选填入 `package_sha256`，公共更新接口同步返回，供客户端下载后做哈希校验。

## Consequences

- 彻底杜绝了断网多开和主动退出轮换租号黑产。
- 消除了因服务器 NTP 时钟微调导致的正常客户误封事故。
- 解决了客户重装系统后公钥不匹配被锁死的运维负担。
- 管理员可在管理界面一键多选批量撤销违规授权与批量封禁黑产设备。
