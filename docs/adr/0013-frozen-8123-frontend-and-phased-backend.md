# Decision: 冻结 8123 前端并按阶段适配后端

- 状态：accepted
- 日期：2026-08-21
- 领域：前端入口、后端接线、阶段交付、验收和变更隔离
- 相关：ADR-0010、ADR-0011、ADR-0012

## Context

产品负责人已经确认 8123 静态页面是未来授权端 Web 管理页面的最终版本：管理端使用 `manage.html` / `manage-login.html`，下游端使用 `downstream.html` / `downstream-login.html` / `downstream-register.html`。此前文档和旧 PR 同时出现静态 HTML、Django 页面路径和 8143 入口，导致静态页面确认被误读成重新设计页面或自动恢复旧后端 PR。

现在需要把后续开发规则固定下来：页面不再变化，后端负责兼容页面；开发按阶段推进；每个阶段必须有完整用户链路、真实验证、只读终审和本地恢复点。

## Decision

1. **前端入口唯一且冻结。** 本地基址是 `http://127.0.0.1:8123/`，部署时只替换域名，后缀保持不变。根路径不自动变成管理端页面，不创建 8143，不增加用户可见的替代页面。
2. **后端适配既有页面。** 不重做 HTML 结构、视觉、导航、文件名或页面层级。阶段内可以修改既有 JS 的 API 接线、认证状态以及已有状态区域的加载/空/失败/权限反馈；如果需求无法在现有页面合同内表达，先记录阻塞并请求产品决定。
3. **页面合同和 API 合同分离。** 页面文件名不推导 Django URL。B0 先建立页面动作、API、服务、权限、数据和反馈的映射，具体 API 写入 `docs/API-CONTRACT.md`。旧 Django 路径只可作为内部后端合同，不能替代 8123 页面。
4. **优先同源接入。** 生产使用同一正式域名提供静态页面和 `/api`，由反向代理转发到 Django；本地可以让 8123 静态服务代理到内部后端端口。浏览器不依赖跨端口 Cookie、宽松 CORS 或跳过 CSRF，也不把 8143 作为集成方案。
5. **首次建设阶段映射（已完成）。** 当时中央平台路线为 B0 接线基础、B1 身份、B2 目录、B3 额度、B4 发卡监管、B5 授权风控、B6 运营安全、B7 G-001 终审。该顺序不再作为当前自动任务；新改动由STATUS与对应功能/API合同限定，保留阶段证据用于追溯。
6. **阶段完成必须可证。** 每个阶段结束前逐项执行 A-101 至 A-111，检查需求去向、完整链路、服务端权限、正常/失败路径、事务、幂等/并发、真实页面接通、文档代码测试一致性、状态标记、关键风险和变更隔离。缺少环境证据必须保持 `active`、`blocked` 或 `not verified`。
7. **客户端接入隔离。** 授权A、LocalBroker、核心EXE和跨目录联调在旧计划中归属PR-20；现行按接入说明00，下载JSON并在指定软件项目使用模板副本，不因中央平台页面冻结或 B0-B7 计划而混入 Web 阶段。

## Alternatives

- 重新制作一套 Django 模板页面：不采用。会产生第二套页面合同，重新引入页面漂移和入口混淆。
- 将 8143 作为新的真实前端服务：不采用。8123 已是唯一冻结的前端基线，端口变化不能解决 API、权限和数据链路问题。
- 直接按旧 PR-13 至 PR-23 顺序开发：不采用。旧 PR 是历史工作包，必须先映射到 B0-B7 并按最新页面合同复核。
- 只依赖 Git checkpoint 防止遗漏：不采用。Git 负责代码恢复，需求追踪还需要 FEATURES、ACCEPTANCE-MATRIX、STATUS、Feature Guard、自动化测试和阶段终审。

## Consequences

- 前端视觉和入口可以稳定下来，后续主要工作是 API/会话/服务/数据库/权限的真实接线。
- 同源部署会减少 Cookie、CSRF 和 CORS 变量，但需要 B0 明确本地代理和部署反向代理配置。
- 页面无法表达的新增能力必须先经过产品决定，不能由开发自行增加页面来掩盖设计缺口。
- 旧 Django 路由可以暂时保留为代码或历史合同，但必须标注其内部性质；是否删除另行授权。
- G-001 的“可部署”不会被静态预览、SQLite 跳过或单个成功演示提前满足。

## Status

accepted
