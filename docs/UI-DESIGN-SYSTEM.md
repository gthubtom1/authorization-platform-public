# UI / 产品逻辑 / 设计品味

## 设计命题

产品不是“卡密 CRUD 后台”，而是一间“授权控制室”：管理员看控制面、下游看生产面，所有额度和授权动作都像账本一样可解释、可回溯。

目标用户需要的是确定感：我现在有什么额度、这次操作会消耗多少、哪些客户正在使用、撤销之后会发生什么。界面应该像精密的运营工具，而不是营销网站。

本设计基线吸收了 [UI-REFERENCE.md](UI-REFERENCE.md) 中 Carbon Data Table、Ant Design Table 和授权产品资料的交互经验，但不直接采用它们的默认视觉或整包代码。

## 简化优先级

最新产品要求是“功能齐全，但页面不复杂”。页面复杂度按以下顺序控制：

1. 每页一个主要任务和一个主按钮。
2. 管理端和下游端的每个列表都默认直接显示全部适用筛选，不使用“更多筛选”、折叠抽屉或隐藏第二行；空间不足时筛选区自身横向滚动，控件保持可用宽度。
3. 所有列表行必须保持单行：单元格不以主、副两行堆叠，长内容使用合理列宽和表格容器横向滚动，不压缩成上下两行。卡密库存只显示未激活卡；已激活卡的设备、IP、激活与到期信息只在设备页和详细操作记录中显示。
4. 低风险新建采用单表单和行内成本预览，不使用可合并的多步向导。
5. 总览只保留关键状态、待处理事项和快捷入口，不重复软件目录、审计表或单卡详情。
6. 去掉英文眉题、页内说明书式说明、说明横幅、装饰性时间线和无业务作用的卡片。标题、数字、状态和按钮保留；字段下方长解释、指标公式和“该怎么操作”的段落不出现。静态预览身份只在顶栏保留一个小标签。
7. 同一业务只有一个事实入口：软件配置只在“软件与套餐”，下游套餐价格随发卡选择展示，单码列表承担查找与排障，详情承担脉络。

2026-11-16交互收口：已有可多选列表统一“筛选 → 明确选择 → 普通动词 → 一次影响确认”。按钮只命名“回收、作废、归档、删除、加时间、撤销授权、封禁设备、解封设备”，不另建批量中心。已选数量集中显示一次；零选择禁用处置，不能隐式作用于筛选全集。表头只全选本页；明确点击“选择全部筛选结果”后冻结匹配ID，达到接口上限时要求缩小范围，禁止静默截断。翻页保留并显示已选范围，修改筛选或搜索清空旧选择。确认框冻结目标，提交结果未知时保留原路由、正文和幂等键，重开仍重试原请求；已成功后读取失败只提示刷新失败，不再次写入。只读审计/流水不增加处置，编辑参数、改密、改版本号仍针对单个对象。

全集读取以服务端实际分页为准，不能假设请求page_size等于响应条数。最多收集500个唯一稳定ID；一次读取最多500页且每页必须有新增记录，页号、总数和has_next一致。重复编号、缺失编号、总数变化或未读完整时保持原选择并提示重试；超过500明确要求缩小范围。所有校验通过后一次性替换选择；取消行勾选和筛选变更继续通过generation使迟到响应失效。

关键词：矿物灰、深墨蓝、信号蓝、账本黄、停止珊瑚、松针绿。

- 标题：`Barlow Semi Condensed`，中文回退 `Noto Sans SC`；用于形成窄而有控制感的页面标题。
- 正文：`Noto Sans SC`，英文回退 `Inter`；保持长表单和说明的可读性。
- 数据：`IBM Plex Mono`；用于卡密、Software ID、额度数字和时间戳。不用于展示批次号。

字体不可用时使用系统回退，不因为字体加载失败破坏布局。

## 布局

- 左侧导航宽度约 232px，固定显示当前工作域。
- 顶部栏显示当前软件、当前下游筛选、只找完整卡密入口和账号状态。
- 内容区域主栏最大宽度 1560px，宽屏两侧可留白；侧栏约占 232px。
- 页面采用 8px 间距基准，卡片圆角不超过 10px，表格和流水优先使用细线分隔。
- 操作按钮使用动词：`生成卡密`、`回收卡密`、`撤销授权`、`保存设置`，不使用模糊的 `提交`。

## 记忆点：授权脉络线

每个详情页在标题下方提供一条“授权脉络线”，按时间展示：

```text
生成 → 分配 → 激活 → 设备绑定 → 验证 → 到期 / 撤销
```

它是本产品的签名组件，出现在**单卡/单码详情页**标题下方。总览不展示授权脉络。用户无需翻多个页面，就能理解一张卡、一个设备或一笔额度发生过什么。

### 管理端

```text
总览
软件与套餐
下游
授权卡密
额度
设备与授权
客户端与版本
审计
备份
```

统计分析从总览进入，版本发布从“客户端与版本”进入；它们保留完整页面，但不占用一级导航。备份页用于打开变动备份或定时备份、设置北京时间全量时间和增量间隔、填写 GitHub、查看最近备份，以及在空站点核对北京时间后导入备份。开关、定时计划和 GitHub 始终在同一屏上方；备份记录和下载加密备份用页内 Tab 切换，导入备份仍是第三个页签。不是新一级导航、不是弹窗。备份去向只有本机加密包和可选 GitHub，页面与 API 都不再配置网盘。

### 下游端

```text
工作台
授权卡密
额度
设备
渠道设置
操作记录
```

可用套餐不再作为重复一级页面；生成卡密时直接显示当前软件、套餐、有效期、设备数和成本，并提供按需查看全部套餐的轻量入口。

导航按“用户要完成的任务”命名，不按数据库表名命名。

管理端“授权卡密”只做全平台未激活库存监管：查询、完整码搜索、交付、归档和回收。管理员不能代下游发卡。下游端只能为当前登录下游发卡；已激活卡从卡密库存移出，转由“设备”承担排障。设备重置只解除当前设备绑定，授权到期时间和套餐快照不变；成功文案必须跟该行最新绑定事实走，封禁后不得写成已解绑。统计分析必须显示指标口径和筛选范围，版本发布必须显示文件校验与发布状态。

全页业务表固定分页大小为 10 个行位；同页有多个表格或需要保留操作区的紧凑页面可以显式使用 5 个行位。真实记录不足时保留不可操作的空白行位，保证表格高度稳定；无匹配数据同时使用局部空态。页码、稳定排序和筛选条件必须可由 URL 恢复，不提供 10/20/50 切换。窄屏时表格在自身容器内滚动，不让整个页面横向溢出。

下游“操作记录”是排障总账：记录下游本人发卡、回收、登录等操作，以及客户端激活、验证、换机和设备重置等事件。默认提供“全部 / 我的操作 / 客户端”快速筛选；卡密/额度码等凭证摘要脱敏，设备 ID、IP 和其他非凭证业务字段按当前读侧权限明文展示；审计记录不可删除。

### 软件授权 A 页面（客户端侧）

授权 A 页面不是中央平台后台的复制版，而是最终客户使用的轻量入口。它只负责“输入卡密 → 查看结果 → 联系下游 → 获取更新提示”，不展示管理员字段、额度流水或其他软件数据。

```text
┌──────────────────────────────────────────────────────────────┐
│ 软件名称 / 版本                         授权状态：未激活       │
├──────────────────────────────────────────────────────────────┤
│ 授权卡密  [____________________________] [激活]              │
│                                                              │
│ [购买卡密]   [联系 QQ]   [联系微信]                          │
│ 没有配置的入口不显示；QQ/微信默认复制或调用固定安全动作      │
├──────────────────────────────────────────────────────────────┤
│ 授权信息：到期时间 / 设备 / 服务端时间                       │
│ 公告与更新：版本、说明、校验状态（无内容时隐藏）             │
└──────────────────────────────────────────────────────────────┘
```

产品逻辑固定为：最终客户在授权 A 输入卡密，A 调用中央平台并按真实归属获取下游的购买链接和联系方式；A 缓存后通过 `authorization-a-core.v1` 传给核心。空值隐藏，不能拿其他下游的默认值补位。QQ/微信值按纯文本展示，按钮只执行客户端内置的复制或受控打开动作，不能执行服务端下发的任意 URI、脚本或命令。

### 下游生成卡密

流程必须是：


确认层必须明确展示：

- 单卡消耗额度
- 生成数量
- 总消耗额度
- 生成后的剩余额度

### 撤销授权

撤销必须选择范围：授权实例、设备、卡密或下游。必须填写原因，并显示“何时对客户端生效”。撤销后详情页保留完整历史。

## 组件规则

- 表格首列固定为对象名称或卡密尾号，完整敏感值用按需显示。
- 详情页右侧使用操作区，危险操作放在分隔线下方。
- 状态标签必须区分：未激活、已激活、已过期、已禁用、已撤销、已回收。
- 额度金额使用等宽数字和正负号，增加额度使用松针绿，扣除使用珊瑚或深墨色。
- 所有批量操作都显示选中数量和影响范围。
- 界面不再提供批次页。邀请码、额度兑换码和授权卡密都只按单码列表展示。一次仍可生成多张，结果立刻进入列表。后台若保留内部生成分组，不得出现在 URL、表头、下载名或用户可见文案。
- 邀请码和额度兑换码不预绑下游、未使用前无期限且一次性；授权卡密绑定下游、未激活前无期限，首次成功激活后才产生授权到期时间。
- 单码与业务工具栏按类型提供状态和业务字段筛选，全部适用条件默认可见；不得把任何条件放进“更多筛选”。授权卡密库存提供软件、套餐、设备与期限筛选；下游端隐藏无意义的下游筛选并固定当前归属。
- 完整码精确搜索是单码排障入口。列表默认脱敏，授权后可显示/复制完整值且不写“谁看过”审计；真实 Web 端使用服务端哈希匹配，不把完整码放入 URL、日志或页面隐藏字段。
- 只有未激活授权卡可勾选回收；也可回收当前筛选中的全部未激活。两种路径都必须显示张数和返还影响。不能把“部分回收”做成整批暗回收。不再提供「回收本批」。
- 导出前显示数据范围、字段和敏感字段提示。
- 每个列表固定声明分页大小 `10` 或 `5` 个行位；表头、筛选和批量工具栏固定在当前列表上下文内，真实数据不足时保留不可操作的空白行位，分页控件固定在表格底部右侧，空筛选使用局部空态，加载状态使用独立加载视图。
- 长列表只在表格区域内部滚动，必要时固定表头和关键列；不得让用户滚动整页才能看完一个 Tab 的数据。
- 默认使用紧凑密度；组件之间只保留能表达层级的留白，不用大面积空白填充布局。
- 新软件使用单表单，名称为主要必填项；授权规则已预填并可展开修改，高级Profile/目标/架构/通道按需修改，首个套餐可选，创建后或软件行下载对应JSON。
- 审计和操作记录主表只显示时间、操作人/来源、事件、对象、结果和详情入口；IP、request_id、原因码、前后变化下沉到详情，避免把排障首页做成日志字段仓库。
- 表格、详情、表单和结果页必须使用一致的局部加载、局部失败和重试模式，不能因一个区域失败而把用户误导回登录页。

## 文案和状态

- 使用简短、主动、具体的中文。
- 空状态告诉用户下一步，例如：`还没有软件。先创建一个软件，再配置套餐。`
- 错误说明事实和处理方法，例如：`额度不足 150，当前可用 80。请减少数量或充值。`
- 不使用“系统异常，请稍后再试”作为唯一错误信息。
- 加载状态说明正在做什么：`正在核对额度并生成卡密…`
- 危险操作不使用恐吓式文案，而是说明不可逆后果。
- 生成邀请码、卡密和额度兑换码后，授权用户可以再次查看、复制或下载；不写“谁看过”审计。密码不能回显，只能重置。
- 每个软件在“软件与套餐”维护自己的卡种、有效期、设备数和单卡额度成本；平台按软件数量扩展，不维护全平台统一价。同名卡种价格可以不同。“软件与套餐”主表的套餐列只显示套餐数量和名称色块，超过可视宽度显示 `+N`；操作列只保留一个“套餐管理”入口。点击后在独立弹窗中查看完整套餐表，顶部统一“新增套餐”，行内提供“修改”；未归档行提供“归档”，已归档行提供“恢复”和“删除”。删除必须确认：该套餐从列表消失，发出的卡（未用和已用）全部失效，不能恢复。弹窗状态列区分可用、仅测试和已归档，归档不得写成「已暂停」，已删除套餐不出现在色块和弹窗。下游“可用套餐”按软件分组显示名称、有效期、设备数和单卡额度，只有“生成”动作，不出现管理操作。
- “设备与授权”必须先搜索再处置：搜索支持授权 ID、设备 ID、卡密对象 ID、软件、Profile、套餐、下游或 IP；结果服务端分页，筛选和导出使用同一条件；`device_state` 与 `risk_state` 分轴，授权芯片跟实例状态；设备 ID/IP 按当前读侧权限明文展示；重置/封禁仍使用短期处置引用，引用不等同展示用设备 ID。

## 新软件接入流程

`填写名称 → 创建软件 → 下载接入 JSON → 软件项目使用模板副本 → 真实接入和验收`。

单表单默认只要求软件名称，授权规则已预填且可展开修改，首个套餐可选。主表单展示只读标识占位，实际 ID 由服务端生成，不能手工覆盖；Profile/系统/架构/通道默认值在高级接入中可改。创建结果及软件列表的对应行可下载配置，下载成功不能标记客户端已接通。切换软件/Profile 后不可沿用另一身份的下载参数。

## 响应式和无障碍

- 功能文字（状态、筛选、按钮、表格、分页、统计说明）最小11px；手机入口说明保持可见，不用0px隐藏。正文与表单继续保持现有较大字号，不能用缩放或CSS transform绕过可读性下限。
- 管理端优先桌面，但表格在窄屏可横向滚动，关键操作不能被隐藏。
- 所有键盘焦点可见，颜色不能是唯一状态信号。
- 支持减少动画；动效只用于页面进入、状态变化和操作反馈。
- 任何表单都要有标签、错误位置和重新提交策略。
