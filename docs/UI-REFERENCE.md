## 我们采用的页面规律

### 仪表盘

仪表盘不是一排相同大小的数字卡，而是三层信息：

```text
当前状态 → 需要处理的事情 → 进入详情的下一步
```

管理员先看额度、授权、风险和待处理动作；下游先看“还能生成多少授权”。每个数字必须带统计口径、时间范围和当前软件/下游筛选。

### 表格

每个列表页默认有：

- 页面标题、当前软件/Profile 上下文和一个主动作；
- 同一行的搜索和当前列表全部适用的状态/业务筛选；空间不足时筛选区自身横向滚动，不使用“更多筛选”隐藏条件；列显示和刷新按需展开；
- 全页表固定 `10` 个行位，紧凑双表页固定 `5` 个行位，不提供行数切换；
- 操作区使用普通动词，零选择禁用处置；选择一条或多条共用动作，集中显示“已选 N 条”和影响范围；本页全选与选择全部筛选结果明确区分，修改筛选清选择；
- 表头固定、列宽稳定，长表格只在表格区域内部滚动；
- 详情用展开行或详情抽屉承载，不把大量字段塞到主列表；
- 空状态、加载状态、局部失败和重试按钮，而不是空白或“系统异常”。

页面不允许为了放卡片而制造大面积空白，也不允许让用户滚动整页才能看完一个表格。窄屏时表格可以横向滚动，但主动作和状态不能消失。

### 详情页

详情页标题下使用“授权脉络线”：`生成 → 分配 → 激活 → 绑定 → 验证 → 到期/撤销`。右侧放当前允许的动作，危险动作与普通动作用分隔线区分。历史、额度、设备和审计必须能从同一对象跳转查看。

### 表单和向导

产品负责人只填写“用户名、密码、数量、软件、套餐、原因”这类业务字段。`adapter_key`、`profile_id`、schema 和哈希属于自动识别或高级只读信息。

普通生成使用一个表单：填写必要字段时同步显示成本或影响，确认后进入结果。回收和撤销使用一次确认；只有版本发布这类确实需要文件校验的高风险流程才使用分步向导。

普通生成链路：

```text
填写并同步预览成本/影响 → 确认 → 结果 → 可追溯详情
```

客户端更新使用：`选择软件 → 上传包 → 自动读取 manifest → 检查版本/哈希/签名 → 确认发布 → 保留旧版本可撤回`。公告不作为独立主流程；更新说明随版本发布展示。

## 复杂度上限

- 一个页面只承担一个主要任务，只显示一个主按钮。
- 总览只回答“现在是否正常、哪里需要处理、下一步去哪”，不重复展示软件目录、完整审计、单卡脉络或配置表。
- 一级列表只用于查找和比较；选择一行后再进入详情、单码、设备或历史。
- 普通用户默认看业务词汇；Profile、适配器、Schema、哈希和原始 JSON 收进高级区。
- 不用英文眉题、说明横幅、装饰性进度线或多层卡片增加页面层级。
- 不为同一动作建立两个入口。总览只能导航；下游套餐价格在发卡流程中查看，不再维护独立的重复套餐工作页。
- 功能完整性由入口可达、权限、数据链路和状态覆盖证明，不由页面数量、卡片数量或同时显示的控件数量证明。

## 凭证显示的产品规则

旧项目已经确认卡密、邀请码、额度兑换码和旧版凭证需要在有权限时可再次查看、复制或下载。这个需求不等于把秘密写进日志：

- 数据库存哈希用于查询，必要时保存加密密文；
- 管理员按需点击“显示/复制/下载”；本项目冻结为不写“谁看过”审计，见 ADR-0010。
- 页面明确显示软件、用途和敏感提示；不显示批次号；
- 密码不提供“查看原文”，只能重置；
- 日志、截图、错误和导出默认脱敏。

## UI 验收底线

每个页面、字段和按钮都要走一次真实角色流程，不以“按钮能点击”为通过标准。至少验证：正常、空值、格式错、重复、边界、连续双击、刷新/后退、网络失败后重试、权限越界和审计结果。

每一步同时核对四层事实：页面显示、接口响应、列表/详情持久化、审计/余额/状态关联。失败注册不能留下账号，失败保存不能覆盖新值，生成数量和实际扣款必须一致，旧页面不能显示成功后的旧状态。

## 明确不采用

- 不整包合并 Keygen、License Mate 或任何 GitHub 仓库。
- 不使用没有清楚许可证边界的源码作为底座；`keygen-sh/keygen-api` 当前 GitHub 元数据为 `NOASSERTION`，只作领域研究。
- 不为了“万能”把每个软件做成一套复制页面、复制 API 和复制数据库表。
- 不使用满屏渐变、无意义玻璃拟态、过多圆角或默认八块统计卡。
- 不把原始 JSON、协议密钥、管理员 Token 或密码放进普通用户流程。
