# 外部研究与复用边界

更新时间：2026-08-23

## 当前事实

本项目当前没有把外部竞品页面、第三方 SaaS 或未核验的代码直接当作业务合同。现阶段的真源是 `docs/PROJECT.md`、`docs/DOMAIN-RULES.md`、`docs/API-CONTRACT.md`、`docs/SECURITY-BASELINE.md` 和冻结的 8123 页面入口。

## 可复用的行业共识

- 认证使用成熟框架的密码哈希、会话、CSRF 和服务端权限校验。
- 额度使用不可变流水，卡券和授权实例分开建模。
- 敏感卡券默认脱敏，管理员在明确权限范围内按需显示、复制或下载；完整码不进入普通列表、URL、日志、隐藏 DOM 或通用导出。
- 具备副作用的请求使用持久幂等键、请求摘要和可追责审计。

## 不直接复用的部分

- 不把竞品的批次页面、零售价、代理层级、离线授权或自定义加密协议带入当前产品。
- 不把任何竞品的管理员密码、密钥托管方式、数据模型或客户端协议当作本项目事实。
- 外部研究只能提供待验证的设计线索；进入实现前必须重新落到当前合同、测试和真实入口。

## 研究缺口

本轮重点是本地代码、真实 8123 候选和 VPS 只读残留核查，没有新增外部竞品调研。需要对外部产品做正式比较时，另行记录来源、访问日期、可复用结论和不采用原因，不修改本文件中的当前业务事实。

## 2026-08-23 备份与迁移研究

本轮通过官方文档核对了备份方案的边界，结论只用于本地候选合同和部署准备，不代表已经连接或写入任何远端资源：

| 来源 | 学到什么 | 本项目采用/避开 |
|---|---|---|
| [PostgreSQL Backup and Restore](https://www.postgresql.org/docs/current/backup.html)（2026-08-23） | PostgreSQL 官方把 SQL dump、文件系统级备份、连续归档/PITR 分成不同能力，各自有优缺点；有价值的数据应定期备份。 | 采用“逻辑备份 + 隔离恢复验收”，PITR/WAL作为原候选研究方向，当前Docker逻辑导出不承诺PITR；不把 VPS 根盘上的单个 dump 当成灾难恢复。 |
| [pgBackRest User Guide](https://pgbackrest.org/user-guide.html)（2026-08-23） | 成熟工具把 WAL、加密、保留策略、恢复、监控和多个仓库作为独立配置，并支持 S3 兼容对象存储等远端仓库。 | 原候选研究pgBackRest，运行形态后由ADR0014的取代说明更新为加密完整dump；保留异地副本与恢复验收原则，不把逻辑dump冒充PITR。 |
| [restic Introduction](https://restic.readthedocs.io/en/stable/010_introduction.html)（2026-08-23） | restic 的仓库本身加密，官方流程包含初始化、快照、恢复和 `check`/`check --read-data` 完整性检查。 | 可作为文件/导出物加密异地备份候选；每次备份必须有完整性检查和隔离恢复，不把 Git 仓库当作 restic 仓库。 |
| [GitHub Docs: Duplicating a repository](https://docs.github.com/en/repositories/creating-and-managing-repositories/duplicating-a-repository)（2026-08-23） | GitHub 官方页面说明的是仓库复制/镜像流程，解决 Git 对象和版本历史复制，不定义 PostgreSQL 一致性快照或密钥恢复。 | 当前私密GitHub库可额外保存加密.enc与恢复清单；不上传明文数据库 dump、`.env`、卡密密钥或备份口令，也不把它作为唯一恢复位置。 |

### 固化结论

- 远端备份必须至少分成“数据库事实”“对象存储/上传包”“版本绑定密钥指针”三类；迁移时三者缺一不可，否则旧卡密、未使用卡密或历史授权可能因密钥丢失而无法复检。
- 当前默认本机加密.enc，GitHub是负责人配置的可选额外副本；令牌、加密、保留和远端读回/隔离恢复须分别验证。原研究不是另一套安装或授权指令。
- 备份验收必须包含数量、关系、额度流水可重建余额、卡密密文可解密、迁移状态和审计时间线核对；“文件存在”不算恢复成功。
