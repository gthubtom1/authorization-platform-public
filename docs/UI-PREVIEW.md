# Web UI 原型与审批门禁

## 目的

授权系统部署在 VPS，是通过浏览器访问的 Web 平台，不是桌面 EXE。当前冻结的静态预览使用 `8124`，真实同源 API 网关使用 `8123`；静态预览按文件后缀区分入口，不提供登录后的角色切换：

- 管理端工作台：`http://127.0.0.1:8124/manage.html`
- 管理端未登录：`http://127.0.0.1:8124/manage-login.html`
- 下游工作台：`http://127.0.0.1:8124/downstream.html`
- 下游未登录：`http://127.0.0.1:8124/downstream-login.html`
- 下游未注册：`http://127.0.0.1:8124/downstream-register.html`

`http://127.0.0.1:8124/` 是本地静态预览基址；真实 8123 网关同时提供这些静态后缀和 `/api/v1/`、`/healthz/`。未来部署时替换为正式域名，后缀继续区分页面。这里的静态文件名只属于前端合同，不等同于真实 Django 路由。

在真实 Django 模板调整前，必须先让产品负责人确认静态 HTML 原型的信息架构、流程状态、视觉密度和移动布局。方案 A 下，静态预览只保留空态、表头、筛选、分页和交互骨架，不连接数据库、不合成业务记录，也不能当作业务或容量验收证据。

## 当前审批状态

截至 2026-08-26，产品负责人确认冻结前端合同；静态预览使用 8124，真实同源 API 网关使用 8123。该确认只冻结前端页面和入口地图，不授权创建 8143 页面。

## 原型入口

从项目根目录启动静态预览：

```powershell
python -m http.server 8124 --bind 127.0.0.1 --directory .\docs\ui-preview
```

浏览器以 `http://127.0.0.1:8124/` 作为静态预览基址，按后缀访问：

- `http://127.0.0.1:8124/manage.html`：管理端空态工作台；真实登录后页面由 8123 同源 API 网关提供数据。
- `http://127.0.0.1:8124/manage-login.html`：管理端登录页。
- `http://127.0.0.1:8124/downstream.html`：下游空态工作台。
- `http://127.0.0.1:8124/downstream-login.html`：下游登录页。
- `http://127.0.0.1:8124/downstream-register.html`：下游注册页。

预览文件位于 `docs/ui-preview/`，每个入口可以独立打开；它们不是把两个角色塞进同一个页面的切换器。

## 当前设计约束

- 功能完整不通过增加页面和控件证明。每页只保留一个主要任务和一个主按钮，次要信息通过行下钻或详情按需出现；当前列表适用的筛选直接显示，不隐藏在“更多筛选”中。
- 管理端一级导航为：总览、软件与套餐、下游、授权卡密、额度、设备与授权、客户端与版本、审计、备份。统计分析从总览进入，版本发布从客户端页进入。管理端备份仍是同一个 `[data-screen-panel="backup"]`；同一屏上方是变动备份总开关、定时备份开关、北京时间全量时间、增量间隔、GitHub 和试连/保存/排队全量；页内 Tab「备份记录 / 下载加密备份 / 导入备份」，学下游/额度的 `work-view-shell` + `data-work-panel` + `hidden`；默认备份记录；排队备份钮不放在整页 `.page-heading`。备份去向只有本机加密包和可选 GitHub，页面与 API 都不再配置网盘。
- 下游端一级导航为：工作台、授权卡密、额度、设备、渠道设置、操作记录。套餐价格在发卡时显示，不再作为重复一级入口。
- 总览只保留关键状态、待处理事项和快捷入口，不展示软件目录、完整审计或某一张卡的授权脉络。
- 列表按当前业务类型直接显示全部适用筛选；软件、套餐、下游、设备、IP、到期和卡密状态等条件不进入“更多筛选”，空间不足时由筛选区自身横向滚动；完整码精确搜索仍保留在单码视图。管理端/下游授权卡密主表有状态筛选和行内状态芯片；下游工作台「待回收」必须筛未激活并重拉，不得只切页；默认摘要不得把混排库存写成未激活卡。管理端「设备与授权」授权状态下拉含已阻断；设备「已解绑」只对应绑定 `unbound`，不是非 active 补集；授权芯片跟实例状态；摘要「待处理」用当前其它筛加上风险封禁后的服务端设备行总数。下游设备重置成功提示跟 POST 信封走：绑定仍 `blocked` 时须写仍已阻断、不得写成已解绑或普通已重置。
- 新建软件、生成邀请码、额度码和授权卡密使用单表单与行内结果预览；只有版本包校验和发布保留必要分步流程。
- 工作页去掉英文眉题、页标题下的说明书段落、指标公式和字段长解释；只保留标题、数据和动作。顶栏只保留一个小型“静态预览”标识。
- 管理端和下游端每个工作页铺满主内容区，不再把内容居中限宽、两边留白。

- 管理端优先展示额度、授权、风险三组控制信号和需要处理事项；统计分析和版本发布保留可到达的独立工作域，不能只用 Toast 冒充。空窗口只用局部空态说明该时间范围没有窗口记录，不得把当前授权、风险、日历导出或下游额度/授权/待回收整块藏掉；总览「需要处理」不得用 Toast 冒充已刷新。
- 下游端优先展示可生产额度、一个“生成授权卡密”主动作、激活收入和最近单卡；最近单卡标明最多 3 张，且不跟授权卡密表翻页/筛选走；设备、额度和操作记录进入各自页面。
- 总览只提供“进入软件与套餐”的导航捷径，不直接打开软件配置弹窗；“软件与套餐”是新建软件、后续编辑授权参数和维护套餐定价的唯一管理入口，避免两个看似独立、实际重复的配置动作。
- 2026-11-16 新建软件主要填写名称，主表单展示只读软件标识占位（创建时服务端生成）；授权规则预填，允许折叠修改，高级身份默认 Windows/x64/stable。首个套餐可选，勾选后完整校验名称/有效期/成本，未勾选不生成套餐。创建结果和软件列表对应行可下载本软件/Profile 的接入 JSON。平台保存软件/Profile/生效策略并交付对应JSON，但保存配置不会自动连接、复制或修改授权 A/核心客户端，真实接入状态必须单独确认。创建 POST 已成功、目录刷新失败时，必须说明软件已保存且列表请重试，不得说成保存失败。
- 管理端“下游与经营范围”发行邀请码，“额度账本”发行额度兑换码；两类码发行时都不绑定下游、未使用前无期限且只能成功消费一次。生成流程只填写数量、面额（额度码），不显示目标下游或有效期。历史已过期且从未使用的邀请码保持作废。
- 管理端下游经营范围弹窗：关掉某软件后，该下游该软件未激活卡不能再开通；已开通验证不受影响；未激活仍可回收退额度。开放后默认全部可用套餐。
- 只有下游端提供授权卡密生成入口。管理员不代发；管理端“授权卡密”是全平台总表（查询、完整码搜索、显示、回收未激活）。授权卡密绑定下游、未激活前无期限，首次激活后才按套餐快照计算到期时间。
- 界面不再提供批次。邀请码、额度兑换码、授权卡密都只按单卡/单码列表展示；一次仍可生成多张，结果立刻进入列表。筛选、详情和多选（回收、归档、删除）取代批次页。过期满 30 天等可批量归档；墙钟已到期但状态仍为已激活的卡，管理端「归档选中」与已过期/已撤销/已回收同样可进确认框，未到期已激活仍须先撤销。未激活须先回收。精确搜索仍要完整码，不支持脱敏尾号。审计和额度流水永不删除。
- 单码列表默认脱敏；授权点击后可显示或复制完整码，**不**记录“谁看过”。真实 Web 接入时完整码精确搜索必须走服务端哈希匹配，不把明文写入 URL、日志或隐藏 DOM。授权卡密详情至少显示软件、套餐、下游、状态、激活时间、到期时间、设备和 IP；未激活字段显示“尚未产生”。
- 本合同描述目标业务与交互边界；方案 A 下 `docs/ui-preview/` 源文件保留空态/骨架，不携带静态软件、套餐、下游、卡密、额度、设备、版本或审计记录。源码和候选归档必须通过静态样本/空态结构扫描；真实 Django 仍只通过 8123 同源 API 网关提供数据。
- 每个软件在“软件与套餐”维护自己的卡种、有效期、设备数和单卡额度成本；以后软件再多，也是每软件一份价，互不影响。“可用套餐”只浏览已开放软件的那份目录，生成按钮带入同一个发卡流程，不维护第二份套餐数据。套餐管理弹窗状态列区分「可用 / 仅测试 / 已归档」，归档不得写成下游账号那种「已暂停」；软件主表芯片仍只显示套餐名称。
- 生成授权卡密必须经过“选择软件/套餐 → 输入数量 → 成本预览 → 确认生成 → 立即交付完整单码 → 单卡列表”，且仅下游入口提供该流程。没有可发卡套餐时确认必须禁用并说明请联系管理员或换软件，不得把空套餐画成 0 成本、点确认无声。取消不改变结果；静态预览只表达空态和不执行写入，不合成成功记录。
- 「可用套餐」按当前软件筛选后若可见套餐为 0，必须用局部空态说明请联系管理员或换一个软件，不得真空白，也不得让下游「先建套餐」。
- 管理员可随时修改额度卡购买链接（仅 HTTP/HTTPS），出现在下游登录、注册和工作台。下游可按软件自定义购买额度卡网站 URL 和一段联系方式文本（邮箱、手机、微信等均可）；没填就是空，不顶成 Profile 或其他字段。只影响用该下游卡密激活的授权页。
- 管理端和下游总览显示今日、本月、累计收入；只统计已激活卡密的套餐额度成本，未激活不计。0 成本测试卡激活后仍是 0。单位是额度。管理端累计等于各下游累计之和。
- 兑换额度卡、回收未激活卡、撤销授权必须明确影响范围、不可恢复性或生效时间，并提供取消路径。
- 表格允许局部横向滚动，页面级布局不能横向溢出；窄屏仍要保留当前入口、账号范围和主要动作。
- 全页业务表固定 10 个可见行位；同页存在多个表格或需要保留操作区的紧凑页面可显式固定 5 个行位。数据不足、筛选为空或最后一页不足时用不可选择、不可导出的空行补足行位，真实记录总数仍按实际数据计算；不提供 10/20/50 切换。
- 管理端显示全平台范围；下游端明确显示“仅当前下游范围”，不展示其他下游数据。
- 静态预览只表达页面结构、空态、筛选、分页、加载、错误、取消和不执行写入的反馈；不伪装真实文件写入、哈希签名、数据库统计、下载、敏感卡密复制、服务端错误或网络失败已经发生。真实版本、统计、清理和凭证交付只在 8123 API 模式验收。

## 原型批准条件

- 管理端和下游端的每个 `[data-screen-panel]` 都必须是 `.app-main` 的后代；浏览器自动纠错后落到 `body` 的页面一律失败。
- 每次导航后必须恰好有一个可见面板，活动导航、面包屑和 URL 状态一致；浏览器前进或返回到无 Hash 地址时恢复各入口默认页。
- 可见面板的横向边界必须落在主内容区域内，不能先出现整屏空白再在侧栏底部显示内容。
- 桌面、`900px` 和 `390×844` 三档都要逐一点击管理端 10 个页面和下游端 7 个页面；不能只检查首屏、页面级 `scrollWidth` 或控制台。
- 发卡弹窗的真实 8123 API 模式必须使用同一份目录和成本预览；8124 静态预览只显示空态占位和禁用写入，不合成成本或余额。非法数量仍需保留在输入框中并显示具体错误，不能静默钳制成另一个数量。
- 总览不得出现第二个软件新建/配置弹窗入口；软件页必须能从现有软件进入“软件配置”和“套餐定价”，新建表单与创建结果必须明确显示“尚未接通客户端”的结果状态。
- 邀请码与额度兑换码生成流程必须覆盖必填校验、取消、明确结果和再次查看/复制/下载；表单不得出现目标下游或有效期，结果必须标明“未使用前永久有效、成功使用一次”。
- 四组码表默认就是单码列表；自动化必须用一条完整码精确搜索成功，再验证空结果、默认脱敏、授权显示/复制、详情字段、归档和删除入口。
- 管理端授权卡密不得出现代发/生成表单；下游端只能为自己发卡。生成结果必须展示可交付完整码，后续列表仍默认脱敏。
- 每张业务表必须声明 10 或 5 个固定行位，并在正常、末页和空筛选下保持相同行数；补位空行不能进入页码总数、搜索结果、选择、导出或业务操作。
- 软件登记、撤销授权、额度卡兑换等表单必须有必填与错误状态；空值不能关闭弹窗并显示成功。
- 回收操作从单卡列表进入：允许勾选部分未激活卡，也允许回收当前筛选中的全部未激活（确认页显示张数与返还额度）。已激活卡不可选择。成功回收后必须更新该卡状态。
- 登录目录、管理端登录、下游端登录和下游注册必须分别可预览；入口页只负责导航，不把两个角色做成切换登录。
- 工作台声明的可用套餐必须与套餐页一致；管理端和下游端涉及多软件数据时必须显示当前软件或清晰的全平台范围，避免把一个软件的配置误操作到另一个软件。下游渠道支持切软件后，过期 GET 不得把上一软件填进表单；保存必须跟已加载软件走，加载未完成不得写入当前下拉。
- 搜索、筛选、分页和多步骤按钮要么在真实 8123 API 模式改变服务端数据，要么在 8124 静态预览保持空态并明确提示未执行写入；不能点击后只显示与页面数据矛盾的成功 Toast。
- 每个数据型工作域至少覆盖正常、空结果、加载和局部错误/重试；危险写操作还要覆盖取消、校验失败和明确成功结果。状态切换不得改变其他工作域或角色的数据。版本发布顶卡把已发布列表读失败画成「暂无发布」属于禁止的空/失败混用。
- 版本发布必须完整表达“选择软件 → 选择安装包 → Manifest/大小/哈希/签名校验 → 确认发布 → 结果”，并提供撤回确认；打开上传时软件必须跟版本表当前选择，撤回确认成功或关窗后必须还能再点下一条；前端不得用文件名子串假装已经做了哈希、签名或 Manifest 校验。统计分析必须明确指标口径、软件/下游/时间范围、北京时间边界和无数据状态。
- 页面切换后要把焦点或读屏状态交给新页面标题；无效 Hash 必须归一为默认页状态，URL、活动导航、面包屑和可见面板始终一致。
- 窄屏导航必须让当前页面和剩余入口可发现，不依赖用户拖动原生滚动条猜测还有菜单；表格横向滚动只发生在表格容器内。
- 搜索、筛选和危险操作必须有稳定可访问名称；正文和辅助文字满足普通文本对比度，不以 placeholder 或装饰符号代替标签。
- 原型检查通过只证明 8124 静态文件可以按当前空态合同验收；真实 8123 同源网关另有 API/权限/数据库验收。产品负责人已经确认该版本；确认冻结前端，不授权创建 8143。
