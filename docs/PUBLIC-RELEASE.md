# Public source release

公开仓库使用独立、无历史的源码快照。现有私有 Git 历史包含历史凭据，不能直接推送到公开仓库。本地生成候选不代表已经公开发布，也不代表生产凭据已轮换。

在私有维护仓库提交希望公开的版本后运行：

```powershell
.venv/Scripts/python.exe scripts/build-public-release.py --output D:/tmp/authorization-platform-public
```

构建器固定从自身所属仓库解析一次 HEAD，并按该提交归档，不受调用者当前目录影响。输出目录必须不存在。构建器及其专用测试包含私有映射，留在私有维护仓库，不进入公开快照；公开副本不提供从私有仓库再次脱敏的命令。

生成过程执行以下规则：

- 排除 `.git`、虚拟环境、构建和临时目录、灾备钥匙包、真实 env、数据库、密钥/证书文件和压缩归档；示例配置保留。
- 对全部 UTF-8 文件及文件名统一脱敏，包括测试、接入包和部署材料；写出前检查路径越界和重名冲突。二进制内容同样参与已知私有值与常见凭据模式扫描。
- 设备指纹替换为合法的合成 64 位十六进制测试值，UUID 和显示码使用对应合成值。业务算法和线上身份不变。
- 统一协议文件换行后，重新计算接入包的逐文件大小、SHA-256、来源哈希；保留 `runtime_connected=false/PARTIAL`。公开副本注明经过脱敏，不把私有来源哈希当成公开产物哈希。
- 排除与私有主机布局及钥匙包耦合的 `tests/test_backup_governance.py`。这是公开回归范围的缺口，不能把其缺席或跳过记为通过；其余业务测试继续交付。
- 对最终全部输出执行扫描，写入 `PUBLIC-SNAPSHOT.json`，记录来源提交及排序后的路径、字节数和 SHA-256。清单不包含自身哈希；构建器打印清单 SHA-256。失败会清理本次新建的输出目录。

验证必须从公开候选的工作目录运行，避免 Python 从私有 checkout 导入测试或业务模块。至少执行 Python 编译、Django check/迁移一致性、设备码与交接包完整性测试，以及受影响的账号和授权测试。编译缓存、测试数据库和临时文件应放在候选外或在打包前清理。最终再次逐项核对 `PUBLIC-SNAPSHOT.json`，再建立只有一个根提交的独立 Git 仓库，并生成排除 `.git` 的归档及其 SHA-256。

新机器使用示例配置和受控的外部密钥注入。生产环境仍按 [完整部署 SOP](../部署与恢复/08-完整部署SOP.md) 操作；公开快照不含其中引用的私有钥匙包、口令或现行运行文件。扫描针对已知私有值及常见凭据格式，不能保证发现任意未知秘密，公开推送前仍须检查最终清单和目标仓库。

推荐创建新的空公开仓库承接该独立根提交。公开推送、重写远程历史、撤销凭据和生产密钥轮换分别需要明确授权；不得从现有私有仓库普通 push 或 force push 来替代这一流程。
