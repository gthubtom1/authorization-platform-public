# 配置怎么用，哪些仍由软件填写

先走 00-先读我.md。本页适用于后台下载的 software-bind.v2；旧 v1 空白清单不再作为新接入入口。

| 字段 | 来源与处理 |
|---|---|
| schema / guide_version | 文件及说明版本，模板副本须显式支持，不能静默忽略未知版本 |
| platform.base_url / contract_version | 后台确认的平台与公共合同，映射到 A |
| platform.authorization_public_key / authorization_public_key_id | 真实验签公钥及 ID；未知 key 拒绝，不从网络随意换信任根 |
| software.software_id / profile_id / client_id | 后台已保存身份，不重填、不猜测、不按名称重新生成 |
| software.target / arch / channel | 与真实构建一致的目标身份 |
| software.minimum_client_version | 最低允许版本，不是当前软件版本 |
| software.capabilities | 已登记公开能力，空数组不代表可以猜键 |
| authorization_a / core | 模板副本、本地合同、仅本机、核心不直连平台 |
| api / contracts / ai_handoff | 公共接口路径、原始协议、给软件侧 AI 的完整接入指令 |

软件仍需填写自己的事实：真实当前版本（1.2.3）、图标、核心启动入口、稳定硬件采集、语言框架、受保护功能与能力映射、核心对本机通道的消费/认证、来源版本/哈希和验收证据。通用Windows启动器已实现DPAPI设备密钥和本机签名通道，其他平台仍须适配安全存储。最终客户只输入卡密，不编辑后台身份。

当前包的prepare-config与桌面Binding::load显式支持v2并核对来源及三份合同，真实版本通过--version提供。使用旧模板时须独立评估适配，不把真实配置改成旧占位文件。新包重新下载后比较差异再同步，不能自动覆盖已有软件工作。

配置不带卡密、平台私钥、管理员令牌、下游密码或固定设备私钥。设备身份按运行时合同生成和保存，nonce/request_id/idempotency_key 不得设为全体用户共享常量。

测试站已过期。只用正式站 test_downstream_b 的 test_only/0 成本卡；test_downstream_a 为历史账号，两者口令都禁止改、禁止重置，不新建下游、不用真下游。完成后在软件项目写对接结果，不请求平台 AI 重复登记回填。
