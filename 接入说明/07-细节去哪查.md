# 细节去哪查（不要抄进本夹）

日常按 00 操作。导出的 v2 JSON 已内嵌 09 指令和 protocol 三份原文，软件侧无需管理员账号或 SSH。以下合同用于深入排查，不恢复手工登记回填流程。

开工行为合同以 `00-先读我.md` 为准（购买开浏览器、联系横幅、空值无反应、网盘更新、两套钟、默认间隔 60 秒、已售下次 verify 跟现行间隔、`RATE_LIMITED` 不得覆盖硬失败、测试站已过期，test_downstream_a 仅历史、现行正式站接入测试只用 `test_downstream_b`、两套测试口令都禁止改、交《对接文档》）。字段级、Schema、测试夹具仍以原文件为准，不要在本夹维护第二份字段表。

| 要查什么 | 去哪 |
|---|---|
| 操作步骤、对接结果内容要求 | 本夹 `00-先读我.md` 第 04 节、`09-给软件项目AI的接入指令.md` |
| 检查更新怎么接 | 本夹 `00-先读我.md`、`03-授权A做什么.md` |
| 公共 API 字段、错误码 | `docs/API-CONTRACT.md` |
| A 接入步骤、device_proof 怎么签 | `docs/CLIENT-INTEGRATION-HANDOFF.md` |
| 已实现的通用运行时、构建/启动参数与目标软件缺口 | `软件授权接入包/授权启动器模板/docs/CURRENT-RUNTIME.md` |
| 软件 / Profile / 能力 / 适配器边界 | `docs/SOFTWARE-ADAPTERS.md` |
| 为什么必须是三层 | `docs/adr/0008-product-authorization-adapter-boundary.md` |
| 启动票据 | 下载 JSON 的 `launch_ticket_contract`（源：API-CONTRACT 一次性启动票据节）；响应适用范围见 `response_contracts` |
| JSON Schema | `protocol/authorization.v1.schema.json`、`protocol/authorization-a-core.v1.schema.json` |
| 设备证明 | `protocol/device-proof.v1.json` |
| 换机 / 装机 | `部署与恢复/08-完整部署SOP.md` |

接某个软件时默认**不要**读：

- 开发过程流水、旧审查结论、已删除的联调稿
- `src/` 整树
- `tests/` 整树
- `终审清理保险/`

只有在「平台公共 API 行为对不上合同」时，才由**平台仓库的 AI**去查 `src/`，不要让软件侧 AI 在平台源码里找接入办法。
