# 禁止事项

现行准备流程见 00：下载本软件真实 JSON，使用模板副本；禁止手改 JSON 冒充新软件、让软件侧 AI 登录后台重复登记、回写通用母版，禁止把下载成功当作接入成功。测试站已过期，不再保留连接旧站或在那里发卡的操作步骤。

接授权 A / 核心时，下面这些做了就会接错。

## 调用关系

- 核心 EXE 不准访问中央平台 `/api/v1/`。
- 不准把平台主密钥、管理员密码、数据库密码放进 A 或核心。
- 不准让两个软件共用一份可变缓存或同一个本地端口状态。

## 卡密和身份

- 列表和搜索仍然只认**完整卡密**（平台侧整码 HMAC）。A 不要发明「尾号也能激活」。
- 默认更新：客户端带上当前 `version` 问平台有没有新版本；有则提示。下载优先打开网盘地址。不要把卡密放进网址，不要给 `/api/` 加跨域 `*`。
- 本站 ZIP 是预备通道，谁都能下，会消耗 VPS 流量。不要删掉上传包能力。
- 客户不能在 A 里改 `software_id` / `profile_id` 去用别人的软件身份。
- 不准提交 `downstream_id` 挑选购买链接或联系方式。空的购买/联系不要编假数据；没有就点击无反应。
- 不准新建测试下游或连接旧测试站。接入目标和身份来自下载 JSON；现行测试只用既有 `test_downstream_b` 的 `test_only` / 0 成本卡。
- 正式站不准用真下游登录、发卡、改资料或改密码。也不要用正式站的 `test_downstream_a` 发卡。
- 不准改 `test_downstream_a` 或 `test_downstream_b` 口令，不准管理端重置。平台操作者查凭据按钥匙包 README“从这里开始”，软件 AI 不接收任何后台口令。

## 时间与安全

- 不准用客户电脑时钟代替平台 `server_time` 放行。
- `device_proof` 不对就失败，不要重试到成功、也不要改本机时间绕过。
- 响应签名校验失败必须停，不要「先让用着」。
- 不准只 activate 一次、开着不再 `verify`。
- 不准把两套钟改混：到期用 `expires_at` 本地关；挤机 / 解绑 / 撤销 / 阻断必须等 `verify` 硬结果。
- 不准把 `cache_until` / 验证间隔 /「多久再问一次」写成核心里的到期倒计时（会单机自己关）。
- 不准靠客户端 20 秒硬刷来「看见挤机」，也不要把测试验收间隔写成 15 分钟。
- 不准把限流、暂时连不上当成被挤掉而关软件。`RATE_LIMITED` 不是挤机信号。
- 不准把 `DEVICE_NOT_BOUND` / 被挤掉 / 已解绑当成断网宽限继续用。
- 不准把验证间隔写成核心到期倒计时。改当前策略后，已售卡下次 `verify` 跟现行间隔；不必为改间隔再发卡。
- 不准把 `expires_at` 当成「只有激活时才读一次」的常量。平台管理员给客户补时间（续期）后，A 每次 `verify` 都要把新的 `expires_at` 交给核心；冻住旧值的写法会让补时间对已经开着的软件不生效。
- 不准断网单机常驻。默认offline_grace_seconds=0，失败/429/重试不得延长最后成功验证窗口，超窗必须停。当前v1可用grace_until减expires_at取得策略宽限时长，不能将grace_until绝对值当断网截止，也不能越过卡到期。

## 本仓库（接软件的人最容易踩）

- **不准改本仓库。** 不准改 `src/`、不准改 Nginx、不准改测试站或正式站来「顺便让这个软件能下包」。
- 平台有问题：回到授权平台这个项目，等负责人点头再改。不要在软件目录里改平台。
- 不准为了某个软件在中央平台核心里写 `if software_id == "某某"`。
- 不准把某个软件的A配置、卡密、设备密钥或具体核心源码提交进本仓库；平台维护的未绑定通用启动器源码属于本仓库交付范围。
- 不准因为「要接软件了」去生成第二套平台密钥。密钥看 `部署与恢复/05-密钥永远一套.md`。
- 没负责人点头：不部署、不热更测试站。备份总开关由页面打开；装机和更新只按 `部署与恢复/08-完整部署SOP.md`。
- 版本号只发 `1.2.3` 这种三段数字。

## 权限

只改用户拥有或明确允许再发行的 EXE。权限不清：只读盘点，不做破解、绕过、隐蔽替换。
