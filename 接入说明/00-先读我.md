# 接新软件，从这里开始

现行流程（2026-11-16）：**你在后台新建软件 → 下载该软件 JSON → 把 JSON 和授权模板副本放到软件项目 → 让软件侧 AI 接入 → 验证后使用。** 不再让 AI 登录后台重新登记、手填空白清单和来回回填 ID。

## 你准备什么

| 材料 | 从哪里来 | 放哪里 |
|---|---|---|
| 已开发的软件及源码 | 你的软件项目 | 保留在软件自己的目录 |
| `软件ID-stable-integration.json` | 管理端 → 软件与套餐 → 对应行“下载接入配置” | 软件项目的 `授权接入/` 子目录 |
| 授权 A 模板副本 | 本平台软件授权接入包内维护的通用源码 | 复制到软件项目内，按包内说明准备配置，不覆盖其他软件副本 |

推荐直接复制本平台根目录的 [`软件授权接入包/`](../软件授权接入包/00-先读我.md) 到软件项目，再把后台 JSON 放入包内 `放后台下载的JSON这里/`。包内已有平台维护的通用启动器源码、配置准备工具、公开资料和[产品品牌适配清单](../软件授权接入包/产品品牌适配清单.md)；无需另找启动器。软件侧AI从包内00开始，运行方式见模板内 `docs/CURRENT-RUNTIME.md`。通用包不预装软件身份、卡密或后台账号。

模板里的标题、图标、示例名称、品牌色和用户可见文案只是通用占位内容，不能直接发布。软件侧AI必须从原软件和负责人确认资料中读取正式产品名称、窗口/任务栏/托盘标题、图标、安装器/快捷方式资源、品牌色和文案，并在接入交付前完成替换和残留检查；只复制文件或只导入 JSON 都不算完成。

也可以保留原有源码、`授权接入/软件ID-stable-integration.json` 和独立模板副本。平台维护包内通用运行时，不改外部旧母版，不在平台src/创建某款软件的卡密页。现有桌面入口已接入v2准备结果、真实HTTP/验签、心跳/续期、票据核销、本机通道和动态UI；软件侧仍要实现稳定硬件采集、具体核心功能门、直开保护并实测，导入成功不代表这些目标软件条件已完成。

## 01：在后台创建软件

1. 正式站 `https://auth.example.com/manage-login.html` → 软件与套餐 → 新建软件。
2. 填名称。软件标识由后台生成，默认 Windows/x64/stable、设备 1、60 秒验证、0 断网宽限、允许满员挤机、每日换机 5，可展开修改。
3. 默认不建套餐；已经确定套餐则勾选“同时添加首个套餐”。否则创建后点击该软件的“套餐”再添加。没有套餐不能发卡，但可以准备接入，不会自动开放任何下游。
4. 创建后下载配置，之后也能从对应软件行重新下载。多 Profile 必须使用对应身份；禁止把 A 软件 JSON 交给 B 软件。

配置中的 ID、公钥来自后台已保存数据。不要手改身份、不要靠改 JSON 新增软件，改显示名称也不应重建 ID。

## 02：交给软件项目的 AI

把 JSON、模板副本和下面这段话交给软件侧 AI：

> 请只在本软件项目内接入授权。先读取授权接入目录中平台导出的 software-bind.v2 JSON，其中 ai_handoff 是接入指令，contracts 是对应公开协议。再读授权模板副本的入口说明。使用配置中的真实身份和验签公钥，在本软件副本做好卡密页、真实平台调用、验签、运行中心跳、核心功能门和失效停用。不要改通用母版，不要登录后台重新登记，不要让核心直连平台。先核对模板兼容性和本软件保护位置，再实现并验证；缺真实条件必须标明。最后在软件项目写出《授权平台对接文档》，不包含秘密凭据。

JSON 是纯数据，不是可执行脚本或授权凭证。软件当前版本由软件构建填写，最低支持版本不是当前版本；运行时规则与授权结果以平台签名响应为准。

## 03：准备测试卡（仍在后台操作）

测试服务器已过期，不再连接 retired.example.com。test_downstream_a 是历史测试账号；正式站接入测试只许已有 test_downstream_b。禁止改 test_downstream_a / test_downstream_b 密码、禁止管理端重置，不新建测试下游，不用真下游额度发测试卡。

管理员为当前软件添加 test_only、0 额度成本测试套餐，并只向 test_downstream_b 开放；由 test_downstream_b 在下游端发卡。持续运行、心跳和挤机要用足够长的测试卡，另用短卡验到期。完整卡密不进 JSON、文档、Git 或截图。配置下载不发卡、不加额度、不改经营范围。账号凭据只在平台侧按钥匙包入口读取，软件侧不需要管理员权限。平台操作者的测试下游口令索引是钥匙包 `07-接入测试下游口令/README.md`；先读钥匙包 README“从这里开始”，不把口令放进接入资料。

## 04：三方怎样算接通

| 一方 | 要完成什么 | 不能拿什么当完成 |
|---|---|---|
| 平台 | 身份/策略正确，配置可下载，卡密与公共接口正常 | 只创建软件或下载文件 |
| 模板副本 / A | 配置映射、真实 HTTP/验签、卡密页、心跳、本地合同、失效通知 | 模板能编译、模拟放行 |
| 核心 | 每个受保护功能检查实时许可；直开核心受保护、失效后停用 | 只在外面包一个登录窗口 |

先验单机开着超过两个验证周期不会自己关，再验错卡、到期、撤销/封禁、断网、运行中补时间、购买/联系空值、更新。两台机器才能证明挤机，一台只能记录未验证。

两套钟：到期用 expires_at，再问用 cache_until/next_verify_at；不能混为一个倒计时。默认 60 秒，已售卡下次 verify 跟现行间隔；硬失败不得被 RATE_LIMITED 覆盖。

软件项目的《授权平台对接文档》记录配置 SHA-256、模板来源版本/哈希、软件版本和身份、修改文件、真实证据和未验证项。不再回传“请后台重新登记和回填 ID”的旧任务。平台有缺陷才回平台项目处理，不在软件项目改平台程序。
