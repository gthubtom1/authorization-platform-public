# 核心 EXE 做什么

先按 00 取得配置和模板副本。平台导出不等于核心已受保护：软件侧必须把下面的功能门和实时失效处理接好，不能只增加外层卡密窗口。

核心是软件自己的功能程序。它**不问**中央平台，**不存**卡密去网上验证。

## 必须做

1. 只跟本软件的授权 A 说话：本机 `/local/v1`。
2. 启动时向 A 打开本地会话，之后问 `session/state`，需要时 `refresh`。
3. 只消费 A 给的类型化结果：能不能用、能力开关、到期、公告、**有没有新版本**。更新弹窗和打开网盘由 A 或软件自己做；核心不要去打平台下安装包。
4. A 说锁定、过期、撤销、阻断、断网心跳超时（默认 0 宽限禁止脱机），或本地会话没了：立刻关掉受保护功能。到期倒计时只用票里的 `expires_at`；不要把启动器的再问间隔写成核心到期。被挤掉时由启动器在 `verify` 收到 `DEVICE_NOT_BOUND` 后通知核心关，断网心跳超时也由启动器通知核心关，核心自己不会「到点被挤」或感知断网。
5. **接受运行中更新的 `expires_at`。** 平台管理员可以给客户补时间（续期），`expires_at` 会被推后，不换卡、不用重新激活。A 每次 `verify` 后会把新值推给核心；核心要接受倒计时变长，不要只在启动时取一次就冻住。
6. 校验 A 的本地合同版本；对不上就停。

通用启动器已提供127.0.0.1随机端口的health/session接口及当前A-core签名信封，启动子进程时通过环境交付本地地址、随机bootstrap token与本地公钥。具体核心必须核对身份/版本/nonce、打开会话、钉住该公钥并验签；没有这些材料时直开应拒绝。稳定硬件、可信父子认证、每个功能门和进程树停用仍是具体软件责任，不能拿通用启动器已核销票据代替。

## 不准做

- 不保存平台网址，不调用 `/api/v1/`。
- 不保存、不转发客户输入的完整卡密到网上。
- 不自己算「应该还能用几天」。
- 不把 A 软件的授权结果拿来给 B 软件用。
- 不承诺「绝对防破解」。本机有控制权的人总能改客户端；能不能用仍以平台为准。

## 软件和软件的差别在哪

核心首先按整体授权状态保护业务入口。有细分功能或限额时，再使用后台已登记的命名空间能力键，例如：

```json
{
  "feature.export": true,
  "limit.projects": 5,
  "edition.name": "pro"
}
```

平台按这个软件已登记的能力下发。核心按这些键开功能。不要为了「这个软件比较特殊」去让核心直连平台。
