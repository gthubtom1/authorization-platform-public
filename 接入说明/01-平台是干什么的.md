# 这个授权平台是干什么的

它是一台网上的授权服务，不是某个软件的安装包。

## 三种人

- **管理员**：管有哪些软件、套餐、下游、额度、卡密、设备、版本。
- **下游**（渠道）：只能管自己被开放的软件，用额度生成卡密，给自己的客户用。
- **最终客户**：不登录这个平台。只在**该软件的授权页 A** 里输入卡密。

## 钱和卡怎么走（大概）

```text
管理员给下游额度
    → 下游生成授权卡密（扣额度）
        → 客户在授权 A 输入卡密
            → 平台激活、绑设备、记到期
                → 未激活卡可以回收，额度退回
```

平台不管下游卖多少钱。下游只有一级，没有「下游的下游」。

## 和授权 A 有关的平台事实

平台里每个要接入的软件，至少要有：

- `software_id`：这个软件的稳定名字
- `profile_id`：例如 `stable` / `beta`，同一软件可以有多个接入身份
- 生效策略（几台设备、能不能换机、多久必须在线验证），创建时按默认值保存

套餐是发卡前需要的材料，可以创建软件后再添加。细分能力按实际产品需要登记；没有能力定义时也能按整体授权状态保护功能，不是新建前置条件。

最终客户看到的购买入口和联系方式，跟**发卡的那个下游**走，不是客户自己填一个下游 ID。购买有 URL 时，启动器点一下用系统浏览器打开；联系方式是横幅纯文本，不要当网址跳转。没填就空着：不要显示可点入口，点了也必须没有反应。

更新不是平台替软件装包。管理员在平台登记**版本号**和网盘地址；客户软件问「有没有比我新的版本」，有就打开网盘 URL。本站也可以放安装包，谁都能下，预备以后大流量 VPS，不是默认更新路径。

新接入按 00-先读我.md：后台创建并下载本软件 JSON，把 JSON 和模板副本放到软件项目。套餐可稍后添加。测试站已过期，test_downstream_a 仅历史；现行正式站只用已有 test_downstream_b 的 test_only/0 成本卡，两者口令都禁止改、禁止重置，不新建下游、不用真下游。

## 这个仓库已经定档的是哪一层

中央平台（管理端、下游端、公共授权 API、卡密加密、审计）是本仓库。  
本仓库也维护 `软件授权接入包/授权启动器模板/` 的通用真实运行时。每个软件自己的授权A副本、稳定硬件采集和核心功能门仍在软件项目实施。本夹就是这些项目的入口说明，通用测试不能代替具体核心验收。
