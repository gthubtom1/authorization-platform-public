# 独立直链站

先看[状态与证据](STATUS.md)。本项目单独复制即可维护，数据与授权平台、展示网站独立。

## 本地使用

Windows安装Python 3.12或更新版本：先双击`创建管理员.cmd`，设置自己的账号密码，再双击`启动本地网站.cmd`。默认后台是`http://127.0.0.1:8780/manage/`。启动窗口关闭后服务停止。正常数据在忽略提交的`data/local/`，不能清掉；没有默认账号、密码或文件。

两个快捷入口会建立本子项目的`.venv/`并安装requirements。开发环境也可以用已有Python运行`python start-local.py --create-admin`与`python start-local.py`。

管理端：新建软件→选择文件→上传，名称可不填；复制固定链接供客户下载。更新只选择新文件，链接不变。点击名称看文件信息与校验值；表格直接显示改名、文件信息、恢复上一次、暂停/恢复、删除等操作，不再使用更多菜单。文件页铺满可用宽度，表头/内容/空位都有横纵分隔线；窄屏按钮自然换行。清理历史保留当前、上一份和最近24小时文件。

上传使用1MiB传输分块，文件身份校验仍按8MiB原合同计算，旧未完成任务可继续。进度只显示服务器确认的字节；浏览器发送完本段但尚未收到响应时显示等待确认，不显示本机缓冲速度。分块连接中断会有限回读原任务，按服务器确认偏移恢复；连续无进展最多3次恢复机会，明确4xx不自动重试。仍失败可用同一文件继续，已确认部分无需重传。

“取消”立即停止本地传输，再向服务器确认，取消链路有45秒总等待预算并防重复点击；连接或响应正文超时后显示“取消结果未确认”，原任务继续保留，可重试取消，刷新页面也不会误恢复传输。若服务器已先完成保存，则明确提示文件已保存，不能报取消成功。一般API等待45秒，完整文件校验保存单独允许180秒；后者超时不代表保存失败，继续原任务先查真实状态。

列表每页10/20条，本浏览器记住选择；表头只选本页，翻页/搜索清空选择。设置可改密码，成功后所有旧会话失效。

## 真实本地验收环境

本工作区`127.0.0.1:8780`当前运行的数据是`data/acceptance/`，名称含“本地验收”的文件均是样例。一次性的本地验收登录材料在被忽略的`test-results/local-access.json`，不进入源码包或生产配置。

复跑验收：先用`python scripts/prepare_acceptance.py`生成隔离数据，设置`DL_DEBUG=1`、`DL_DATA_DIR`为本目录`data/acceptance`，再运行`python manage.py runserver 127.0.0.1:8780 --noreload`。`scripts/live_transfer_test.py`通过真实HTTP执行300MB、500MB、1GB以上上传及完整下载校验，并运行实际备份/隔离恢复。浏览器脚本依赖维护工作站的Playwright安装路径，可按实际环境调整，不属于生产运行依赖。

后台回归：`DL_DEBUG=1 python manage.py test files`。测试使用临时数据，不读取正常数据目录的文件。

## 备份与恢复

配置好相同的数据目录和站点环境后执行：

```text
python manage.py backup_site /受保护的外部备份目录/directlink.zip
python restore-backup.py /备份/directlink.zip /不存在的新数据目录
```

备份包含数据库、管理员密码哈希和保留文件，未加密，必须放受保护位置，不作为公开安装包提供。`DL_SECRET_KEY`单独保管；不包含上传临时块。恢复校验清单、大小/哈希、SQLite物理与外键完整性，以及当前/上一份文件的归属和保留状态，清空旧会话并取消未完成上传。恢复只能到新目录；不覆盖运行数据。停站后切换目录，另行检查登录和下载。

大备份持有发布写锁，期间新上传会等待；下载预算使用独立锁，仍可能受真实磁盘负载影响。正式规模需安排备份窗口，不宣称无限并发。

## 部署交接

生产运行代码默认要求`DL_DEBUG=0`、明确域名和独立站点密钥。使用本目录`.env.example`、`deploy/`材料，不复用授权平台卡密/签名密钥。首次管理员由命令行设置，网站没有公开注册。

部署AI按以下流程执行。安装器VERIFY_OK核对本站服务定义、主进程和回环监听、本机HTTPS的Host/SNI、应用/实例及源码身份；不接受无关200或302，但它仍不替代公网业务验收：

1. 将本目录源码放到`/opt/direct-link-site`，排除`.venv/`、`data/`、`test-results/`、`.env`等本地文件。现有数据卷/目录不得覆盖或删除。
2. 准备Python venv支持、Nginx和有效的独立域名证书，选择空闲的本机端口18081，检查同机其他网站。`deploy/nginx.conf.example`只管理此域名，不做其他站的重定向/根路由改写。
3. 准备本项目自己的`.env`，使用独立的Django会话密钥，`DL_DATA_DIR=/opt/direct-link-site/data`，`DL_USE_ACCEL=0`。这不是生成第二套授权平台密钥。
4. 从该目录运行`bash deploy/install-site.sh`；安装器创建专用低权限账号、迁移、静态资源、站点服务与小时临时文件维护timer。这个timer仅清理本站临时上传，不是授权平台备份timer。若源码来自固定时间戳归档，先更新`static/`内本站源码资源的文件修改时间再运行同一安装器，避免collectstatic因旧目标时间较新而跳过；完成后逐字比较源码static、staticfiles与公网响应。不要只看源码健康指纹就认定浏览器脚本已更新，具体实证见根部署记录。
5. 在受控环境注入相同配置，使用本站命令`createsuperuser`创建管理员。不要把口令写进命令历史、源码或文档。
6. 实际验证HTTPS、陌生用户不能管理、上传超过1GB、完整下载/续传、改密旧会话、重启服务、备份恢复及同机其他站保持正常。安装器验证须同时核对本机实例、站点路由、身份和严格成功状态，不用公网任意健康响应代替，更不能代替这些业务证据。

2026-11-17首版已实际执行Linux安装器、Nginx/TLS、HTTPS上传下载与服务重启核验，见STATUS和根部署记录。上传稳定性补丁本地故障注入证据在test-results/upload-network.json；是否已更新到正式站只看STATUS，不从源码存在推断上线。生产模板使用应用流式下载，未开启可选X-Accel发送。不要把本地runserver暴露公网。
